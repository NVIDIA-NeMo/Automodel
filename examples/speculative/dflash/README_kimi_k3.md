# Training a Kimi K3 DFlash drafter

This recipe trains a dense Kimi K3 MLA drafter against the frozen Kimi K3 text
model. The draft preserves the target's MLA projections (Q-LoRA, compressed KV
latent), output gate, fp32-variance RMSNorm, and SiTU MLP; KDA linear attention,
routed and shared experts, MTP, and the learned attention-residual mixer stay in
the target only. `kimi_k3_dflash.yaml` is the reference configuration.

## What differs from the Qwen3 DFlash configs

- `attention_backend: sdpa` is required. The draft's MLA attends over the dense
  additive DFlash mask; it has no FlexAttention path, so the draft spec declares
  `sdpa` as its only backend and `flex_attention` is rejected at setup.
- `num_anchors` is lower than the Qwen3 configs'. The dense mask spans
  `num_anchors * block_size` queries by `seq_length + num_anchors * block_size`
  keys, so anchors are quadratically more expensive here than on the sparse
  FlexAttention path.
- `distributed.pp_size` must be 1. Online hidden-state capture hooks one
  complete, non-pipelined target forward. Shard the frozen target with `ep_size`
  instead.
- `distributed.cp_size` must be 1. K3 declares `_owns_cp_attention` (it shards
  the batch into contiguous slices for its KDA kernels) and so never routes
  through the CP key/value-gather hook the DFlash target wrapper installs.
- `packed_sequence_size` must be 0. K3 declares `_owns_packed_attention` and
  consumes its own packing metadata (a padding mask plus per-document
  `cu_seqlens`), not the block-causal additive mask the target wrapper builds.
- Domino is not available on this target: its GRU correction head is implemented
  on the Qwen3 draft only, and `TrainDominoRecipe` fails loudly against K3.

## Hardware

The target has 896 routed experts, so shard it with expert parallelism and pick
an `ep_size` that divides 896. The provided configuration uses `ep_size: 64`,
i.e. 64 ranks across eight 8-GPU nodes; lower it to fit a smaller allocation.

## Data

`train_data_path` expects messages-format SFT data. If the responses were
generated by a different model than the target, regenerate them with Kimi K3
before a quality run: mismatched responses are fine for a pipeline smoke but
cost acceptance rate.

## Launch

Run the same command on every node, varying only `--node-rank`. Node 0 provides
the rendezvous address.

```bash
torchrun --nnodes=8 --node-rank=<RANK> --nproc_per_node=8 --master-addr=<NODE0_IP> --master-port=29500 -m nemo_automodel.recipes.llm.train_dflash -c examples/speculative/dflash/kimi_k3_dflash.yaml
```
