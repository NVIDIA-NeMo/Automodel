# MiniMax M3 MSA kernels

Forward uses [official MSA at 80434d7f](https://github.com/MiniMax-AI/MSA/tree/80434d7f67877c6570ca19cac444b84bc9855dac); backward lives here.
Install with `uv sync --locked --extra msa` (Linux, SM100, CUTLASS DSL 4.6.2); use `uv run` so torch can find `ninja`.
`../msa_bindings.py` binds the four official entry points (`build_k2q_csr`, `sparse_atten_func`, `fmha_sm100`, `fmha_sm100_plan`) and the local `run_backward` on first use (`kernels()`), applying two patches once: it fixes the official CUDA 12.9 `nvvm.fmax` binding for DSL 4.6.2, preserving fp32 conversion, the third operand and `loc`/`ip` (it checks MSA module ownership and replaces only its helper before JIT; remove the patch when the pinned upstream uses inferred result types), and it separately drops the `sm_103a` target from MSA's own nvcc flags when the local toolkit predates 12.9, which changes build flags only, never what a kernel computes.
Block selection lives beside the model in `../msa.py`: `MSAMicrobatch.select_blocks` scores one layer with the official `fmha_sm100` OnlyScore pass and applies M3's forced/candidate/top-16 rule, sharing the per-microbatch plan and the process-wide score buffer; the Torch definition it is checked against is `tests/unit_tests/models/minimax_m3_vl/_msa_select_reference.py`.
`msa_schedule.py` is the CuTe-free contract of the kernels (the attention topology constants, the saved forward schedule validated when it is built, and the CTA-walk rule the device mirrors); `msa_task_build_sm100.py` builds the locality-ordered task tables and the CTA walk on the device without a host sync; `msa_backward_preprocess_sm100.py` computes delta; `msa_backward_sm100.py` is the main kernel and `run_backward`, the one host entry point (one internal allocation per call, preprocess, pool clear, task build, launch, finalize); `msa_backward_postprocess_sm100.py` casts the gradient pools to BF16.
dK/dV accumulate with FP32 atomics and dQ with packed bf16 atomics (`DQ_ACCUM_DTYPE`; fp16 would keep 3 more mantissa bits, but `red.global.add.f16x2` carries no `.sat`, so an element past 65504 becomes `inf`, and partials below its subnormal range flush to zero: 85% of a 16k dQ at 1e-6-scale output gradients).
The task build has no runtime switches: the locality window (512 queries) and the CTA walk (4 task rows per CTA up to 2400 rows, 64 above) are constants, the Torch reference lives in `tests/functional_tests/models/minimax_m3_vl/test_msa_task_build_sm100.py` as the oracle the device tables are checked against, and a microbatch whose locality bins exceed 2^22 (about 250k tokens) raises `ValueError`.
Validate pin changes with the MSA CPU tests and `tests/functional_tests/models/minimax_m3_vl/test_msa_sm100.py` on SM100; PP=2 requires two GPUs.
