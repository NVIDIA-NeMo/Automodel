## 0.7.0 · 26.10 (2026-10-21) · [PyPI](https://pypi.org/project/nemo-automodel/0.7.0/) · [GH](https://github.com/NVIDIA-NeMo/Automodel/releases/tag/v0.7.0) · [NGC Docker](https://catalog.ngc.nvidia.com/orgs/nvidia/containers/nemo-automodel/tags?version=26.10.00)

### Highlights

- **Expanded model coverage.** New training paths for DeepSeek-V4.1-Flash,
  GLM-5.3-Flash, Qwen3.8-Flash-Next, MiMo-V2.5-Pro and MiMo-V2.6, and additional
  vision-language models.
- **More MoE training options.** Mixture-of-Kittens (MoK) BF16 and MXFP8 experts,
  compact HybridEP routing, and MXFP4-resident DeepSeek-V4-Flash experts for LoRA.
- **Speculative and discrete-diffusion training.** DFlash 2, additional Kimi K3
  and DeepSeek-V4.1 draft-training paths, streaming EAGLE-3 feature components,
  I-DLM training, and SCDD training and sampling.
- **Text-to-image fine-tuning.** HunyuanImage-3.0 with expert parallelism and
  Qwen-Image-2.1 with full-parameter and LoRA recipes.
- **Training and integration improvements.** Native FlashAttention-4, explicit
  packing contracts, weighted domain mixtures, lower-memory checkpoint loading,
  and public registration of custom model architectures.

  vision SFT. The release includes the CP8 gradient-synchronization fix.
  ([model guide](https://github.com/NVIDIA-NeMo/Automodel/blob/d5af786161ba6d2d3cb348558ff26d8cea299af4/docs/model-coverage/vlm/deepseek-ai/deepseek-v4-1-flash.mdx),

### Training, Parallelism, and Performance

- **MoK experts:** Optional `dispatcher: mok` integration for fused dispatch
  and expert computation, plus MXFP8 experts. Supported shapes, precision,
  topology, and adapter combinations are checked explicitly.
  ([#3422](https://github.com/NVIDIA-NeMo/Automodel/pull/3422),
  [#3606](https://github.com/NVIDIA-NeMo/Automodel/pull/3606))
- **Lower-memory DeepSeek-V4-Flash LoRA:** MXFP4-resident frozen experts avoid
  keeping a full BF16 expert copy. This path requires expert parallelism and
  `torch_mm` experts with the torch dispatcher; DeepEP experts are unsupported.
  ([#2548](https://github.com/NVIDIA-NeMo/Automodel/pull/2548))
- **MoE and Kimi K3 efficiency:** Compact HybridEP routing, reuse of DeepEP
  dispatch layouts during activation-checkpoint recomputation, fused gradient
  norm reduction, pipeline receive-buffer reuse, and opt-in Kimi K3 kernels.
  ([#3404](https://github.com/NVIDIA-NeMo/Automodel/pull/3404),
  [#3684](https://github.com/NVIDIA-NeMo/Automodel/pull/3684),
  [#3685](https://github.com/NVIDIA-NeMo/Automodel/pull/3685),
  [#3780](https://github.com/NVIDIA-NeMo/Automodel/pull/3780),
  [#3954](https://github.com/NVIDIA-NeMo/Automodel/pull/3954))
- **Kimi Linear:** Adds packed sequences and context parallelism.
  ([#3243](https://github.com/NVIDIA-NeMo/Automodel/pull/3243))
- **Weighted domain mixtures:** Configure sampling frequency separately from
  each domain's objective weight for Megatron continual pretraining, with
  per-domain token metrics and weighted validation. This initial path rejects
  packing, PP, CP, JSON blends, and other unvalidated combinations.
  ([#3303](https://github.com/NVIDIA-NeMo/Automodel/pull/3303))
- **Correctness fixes:** Expert-parallel gradient clipping, TP replica
  synchronization, TP knowledge-distillation gradient reduction, per-token
  parallel cross-entropy gradients, and preservation of model input/output
  dtypes through FSDP.
  ([#3817](https://github.com/NVIDIA-NeMo/Automodel/pull/3817),
  [#3822](https://github.com/NVIDIA-NeMo/Automodel/pull/3822),
  [#3777](https://github.com/NVIDIA-NeMo/Automodel/pull/3777),
  [#3853](https://github.com/NVIDIA-NeMo/Automodel/pull/3853),

### Compatibility and Upgrade Notes

- **Dependency baseline:** The release branch pins `transformers==5.18.0`
  and requires `torchao>=0.16.0`. The optional PyTorch base stage uses NVIDIA
  PyTorch `26.08-py3`. Use the release branch's dependency files when building an
  environment; individual model guides may still mention older intermediate
  Transformers pins.
  ([package dependencies](https://github.com/NVIDIA-NeMo/Automodel/blob/d5af786161ba6d2d3cb348558ff26d8cea299af4/pyproject.toml),
  [container definition](https://github.com/NVIDIA-NeMo/Automodel/blob/d5af786161ba6d2d3cb348558ff26d8cea299af4/docker/Dockerfile))
- **Optional experiment tracking:** MLflow and Weights & Biases are optional
  extras. Install `nemo-automodel[mlflow]` for the tracking client,
  `nemo-automodel[mlflow-full]` for the full MLflow stack, or
  `nemo-automodel[wandb]` for W&B.
  ([#3785](https://github.com/NVIDIA-NeMo/Automodel/pull/3785),
  [extra definitions](https://github.com/NVIDIA-NeMo/Automodel/blob/d5af786161ba6d2d3cb348558ff26d8cea299af4/pyproject.toml))
- **Custom retrieval loaders:** Pass backbone options such as
  `attn_implementation="sdpa"` by keyword; positional arguments after the
  checkpoint path are forwarded to the backbone constructor.
  ([#3915](https://github.com/NVIDIA-NeMo/Automodel/pull/3915))

#### Native FlashAttention-4

- Select the native CuTe backend with `model.backend.attn: fa4` in an
  `INSTALL_FA4=true` image. On models declaring native FA4 support,
  `model.attn_implementation: flash_attention_4` also selects it when no backend
  config is supplied. An explicit backend config remains authoritative.
  HF-dispatched models continue to use the HF `flash_attention_4` implementation.
- Native FA4 accepts BSHD inputs and NEAT packing. Use `cp_size: 1` and select
  NEAT explicitly for packed runs; legacy THD packing is unsupported. Dense
  attention masks are unsupported. Packed Qwen3Next recurrent attention and
  DeepSeek V3.2 sparse attention are also unsupported by this backend.
- Finite native FA4 windows count visible keys including the current token,
  matching the SDPA window convention. The pinned SM100/SM110 FA4 kernel does
  not support local attention with 256-wide query/key and value heads; select
  `model.backend.attn: sdpa` for that combination.

#### NEAT packing API migration

- Packing now follows the built model's attention dispatch. The legacy YAML
  selector `packed_sequence.attn_implementation` is ignored with a warning.
- Replace `get_attn_implementation(cfg_model, model)` with
  `get_model_attn_implementation(model)` from
  `nemo_automodel.components.models.common.packing`. For multiple local pipeline
  stages, use `configure_packing_for_models(model_parts)`.
- Import `get_unpad_data` and `get_seqlens_in_batch` from
  `nemo_automodel.components.datasets.packing`. HF flash packing uses
  explicit public varlen kwargs without modifying Transformers globals. Pass the
  contract returned by `configure_packing` as `packing=` to
  the collater or `packing_contract=` to the dataloader config's `build()`.
- `VlmDataloaderConfig.resolve_packing_attn_implementation` was removed. Custom
  integrations should configure the built model and supply its packing contract
  to `VlmDataloaderConfig.build()` instead of selecting a backend in the dataset.
- `configure_packing` now requires an attention implementation and returns a
  packing contract. Qwen3.5, Qwen3.5-MoE, Kimi Linear, and Kimi K3 require the
  resulting dataset metadata alongside indexed masks. Custom loops must pass
  the contract to their collater and forward its metadata; the legacy
  `attn_implementation=` collater argument cannot declare model-specific
  metadata requirements.
- Qwen3.5 packing with load-balanced context parallelism now raises instead of
  silently losing document isolation. Use `cp_size: 1`, or the supported SDPA
  block-diagonal CP path for Qwen3.5-MoE.

## 0.6.0 · 26.08 (2026-08-26) · [PyPI](https://pypi.org/project/nemo-automodel/0.6.0/) · [GH](https://github.com/NVIDIA-NeMo/Automodel/releases/tag/v0.6.0) · [NGC Docker](https://catalog.ngc.nvidia.com/orgs/nvidia/containers/nemo-automodel/tags?version=26.08.00)

### Highlights

- **Frontier-scale MoE and multimodal models.** Train Moonshot AI's Kimi K3 (2.8T/104B active),
  Thinking Machines Lab's Inkling (975B/41B active), MiniMax AI's MiniMax-M3 VL (428B/22B active),
  Poolside's Laguna, and Zhipu AI's GLM-5.2.

- **Long-context training.** Shard packed multi-document sequences with block-diagonal
  variable-length context parallelism, and shard vision towers by frame to remove the redundant
  vision compute of a CP fold; recipes reach 128K tokens at EP8/CP32.

- **New attention and kernel backends.** Select FlashAttention 3 and 4, MagiAttention, FFPA for
  headdim=512 layers, QuACK linear/RMSNorm/RoPE kernels, and scoped partial CUDA graphs for MoE.

- **Resilient checkpointing.** Checkpoint on preemption signals, write to `msc://` cloud
  directories, consolidate async saves in the background, bound checkpoint retention, and resume
  past an interrupted save.

- **Diffusion.** Fine-tune and generate with LTX-2.3 joint video+audio and Qwen-Image-Edit-2511, and
  run context parallelism through the diffusers `ContextParallelConfig` API.

### New Hardware and Precision Support

- **FP8 draft training.** Extends the SFT recipes' top-level `fp8:` block to every speculative
  recipe, swapping the draft's `nn.Linear` layers to torchao `Float8Linear` on SM89 and newer, with
  `emulate: true` for older GPUs. ([#2963](https://github.com/NVIDIA-NeMo/Automodel/pull/2963))

- **Quantized checkpoint ingestion.** Dequantizes MXFP4 dequantization for Kimi K3 and MXFP8
  dequantization for MiniMax-M3 for BF16 training, keeps Kimi-K2.5-VL LoRA keys out of INT4
  quantization on save, and fixes a TileLang `boolx8` backward codegen failure on the DeepSeek-V4
  path. ([#3259](https://github.com/NVIDIA-NeMo/Automodel/pull/3259),
  [#3295](https://github.com/NVIDIA-NeMo/Automodel/pull/3295),
  [#3467](https://github.com/NVIDIA-NeMo/Automodel/pull/3467))

  [#2953](https://github.com/NVIDIA-NeMo/Automodel/pull/2953))

- **Metrics and resume.** Reports simulated accept length, per-position `accept_rate@k`, and
  periodic real accept length through `decode_eval`, and rejects a mismatched `mask_token_id`, a
  stale draft-vocab mapping, and mixed precompute shards on resume.
  ([#2959](https://github.com/NVIDIA-NeMo/Automodel/pull/2959),

### Training, Parallelism, and Performance

- **Block-diagonal variable-length context parallelism.** Introduces a `blockdiag_cp` implementation
  that shards packed multi-document sequences while keeping masking block-causal per document,
  driving varlen kernels from precomputed `cu_seqlens` with a fused K/V all-gather.
  ([#2989](https://github.com/NVIDIA-NeMo/Automodel/pull/2989),
  [#3223](https://github.com/NVIDIA-NeMo/Automodel/pull/3223))

- **Unified context-parallel input preparation.** Returns a `ContextParallelSharder` from a single
  `prepare_model_inputs_for_cp` hook and replaces `cp_utils` with
  `components.distributed.context_parallel`.
  ([#2937](https://github.com/NVIDIA-NeMo/Automodel/pull/2937))

- **Frame-level vision-tower sharding.** Partitions frame units across the CP group through
  `distributed.multimodal.vision.frame_sharding` and reassembles embeddings with a differentiable
  variable-length all-gather.
  ([docs](https://github.com/NVIDIA-NeMo/Automodel/blob/v0.6.0/docs/guides/cp-vision-frame-sharding.mdx),
  [#2990](https://github.com/NVIDIA-NeMo/Automodel/pull/2990),
  [#3186](https://github.com/NVIDIA-NeMo/Automodel/pull/3186))

- **Attention backends.** Selects `flash_attention_3` and `flash_attention_4` with a `fa4 → fa3 →
  fa2 → sdpa → eager` fallback ladder, MagiAttention as both a kernel and a context-parallel backend
  with
  [CP1](https://github.com/NVIDIA-NeMo/Automodel/blob/v0.6.0/examples/llm_finetune/qwen/qwen3_moe_30b_magi_packed_sequence.yaml)/[CP2](https://github.com/NVIDIA-NeMo/Automodel/blob/v0.6.0/examples/llm_finetune/qwen/qwen3_moe_30b_magi_packed_sequence_cp2.yaml)
  Qwen3-MoE-30B packed recipes, and a CuTeDSL FFPA backend for Gemma 4's head_dim=512 layers
  ([8K](https://github.com/NVIDIA-NeMo/Automodel/blob/v0.6.0/examples/vlm_finetune/gemma4/gemma4_31b_ffpa_mock_8k.yaml),
  [packed CP8
  16K](https://github.com/NVIDIA-NeMo/Automodel/blob/v0.6.0/examples/vlm_finetune/gemma4/gemma4_31b_ffpa_mock_packing_cp8_16k.yaml)).
  ([#2384](https://github.com/NVIDIA-NeMo/Automodel/pull/2384),
  [#2929](https://github.com/NVIDIA-NeMo/Automodel/pull/2929),
  [#3070](https://github.com/NVIDIA-NeMo/Automodel/pull/3070))

- **QuACK kernels and partial CUDA graphs.** Exposes `quack` options for `backend.linear`,
  `backend.rms_norm`, and `backend.rope`, and `backend.cuda_graph.modules` capture of `attn`,
  `moe_router`, and `moe_preprocess` while dispatch, expert compute, and combine stay eager.
  ([#2917](https://github.com/NVIDIA-NeMo/Automodel/pull/2917),
  [#3115](https://github.com/NVIDIA-NeMo/Automodel/pull/3115))

- **Activation checkpointing.** Accepts `activation_checkpointing: selective` for DDP and an
  `activation_checkpointing_scope` selecting which layer groups are wrapped, and saves the MoE
  router and its top-k output so recompute preserves expert assignments.
  ([#2786](https://github.com/NVIDIA-NeMo/Automodel/pull/2786),
  [#2840](https://github.com/NVIDIA-NeMo/Automodel/pull/2840),
  [#3140](https://github.com/NVIDIA-NeMo/Automodel/pull/3140),
  [#3247](https://github.com/NVIDIA-NeMo/Automodel/pull/3247))

- **Cross-entropy memory.** Supports `FusedLinearCrossEntropy` under pipeline parallelism and bounds
  `ChunkedCrossEntropy` memory with a kernel that saves only original-dtype logits and recomputes
  each softmax chunk in backward. ([#2927](https://github.com/NVIDIA-NeMo/Automodel/pull/2927),
  [#2996](https://github.com/NVIDIA-NeMo/Automodel/pull/2996))

- **FSDP2** Wraps HF transformer layers with PyTorch's non-reentrant `checkpoint_wrapper` to remove
  duplicate prefetch all-gathers, and adds `distributed.multimodal.frozen_sharding` for fully frozen
  towers. ([#3328](https://github.com/NVIDIA-NeMo/Automodel/pull/3328),
  [#3411](https://github.com/NVIDIA-NeMo/Automodel/pull/3411),
  [#3513](https://github.com/NVIDIA-NeMo/Automodel/pull/3513))

- **Gradient correctness.** Normalizes the MoE auxiliary loss by the gradient-accumulation and
  pipeline-microbatch count, all-reduces grad-norm accumulators on the mesh device, and preserves
  HSDP replica gradient synchronization for MoE.
  ([#3135](https://github.com/NVIDIA-NeMo/Automodel/pull/3135),
  [#3359](https://github.com/NVIDIA-NeMo/Automodel/pull/3359),
  [#3461](https://github.com/NVIDIA-NeMo/Automodel/pull/3461))

- **Damaged-embedding repair.** Replaces, through an optional `embedding_row_repair:` section,
  input-embedding rows whose L2 norm is non-finite or below `min_norm` with the scaled
  output-embedding direction; it is rejected under pipeline parallelism.
  ([docs](https://github.com/NVIDIA-NeMo/Automodel/blob/v0.6.0/docs/model-coverage/troubleshooting.mdx#enable-the-repair),
  [#3136](https://github.com/NVIDIA-NeMo/Automodel/pull/3136))

- **Setup-time prewarms and mesh timeouts.** Initializes lazily created resources through an opt-in
  `prewarm:` section covering `cublas_backward`, `fla_gdn_autotune`, `mamba_ssd_autotune`, and
  `comm_groups`, and applies `dist_env.timeout_minutes` to flattened and expert-parallel meshes.
  ([#2846](https://github.com/NVIDIA-NeMo/Automodel/pull/2846),
  [#2992](https://github.com/NVIDIA-NeMo/Automodel/pull/2992),
  [#3296](https://github.com/NVIDIA-NeMo/Automodel/pull/3296))

- **Rollout Routing Replay.** Reuses the rollout's discrete top-k expert selection in the training
  forward through `MoEConfig.enable_routing_replay`, which reuses the rollout's discrete top-k
  expert selection in the training forward to remove the rollout/training routing mismatch in
  on-policy RL. ([#2797](https://github.com/NVIDIA-NeMo/Automodel/pull/2797))

- **Optimizer parameter groups and throughput.** Adds `optimizer.param_group_overrides` with
  `lr_mult` and `wd_mult` multipliers, removes Python overhead from Transformer Engine attention and
  MoE expert hot paths, and shapes `TPLinear`/`LinearLoRA` graphs so async-TP fusion fires.
  ([#2987](https://github.com/NVIDIA-NeMo/Automodel/pull/2987),
  [#3046](https://github.com/NVIDIA-NeMo/Automodel/pull/3046),
  [#3374](https://github.com/NVIDIA-NeMo/Automodel/pull/3374))

- **PEFT under pipeline and expert parallelism.** Gathers adapter weights across pipeline stages
  before writing and saves optimizer state for every PEFT model part namespaced by stage.
  ([#3096](https://github.com/NVIDIA-NeMo/Automodel/pull/3096),
  [#3250](https://github.com/NVIDIA-NeMo/Automodel/pull/3250),
  [#3316](https://github.com/NVIDIA-NeMo/Automodel/pull/3316))

- **PEFT v5 expert adapters.** Exports MoE expert LoRA through an opt-in PEFT v0.18+ ParamWrapper
  export for MoE expert LoRA with fused `target_parameters`, validated on Qwen3-MoE, MiniMax-M2, and
  Nemotron v3. ([#3439](https://github.com/NVIDIA-NeMo/Automodel/pull/3439),
  [#3458](https://github.com/NVIDIA-NeMo/Automodel/pull/3458))

- **LoRA correctness.** Makes `use_memory_efficient_lora: false` also suppress the fused
  SwiGLU/ReLU² LoRA MLP, restores adapters through DDP wrappers, and reaches the absorbed GLM MLA KV
  weight through a new `materialize_effective_weight()`.
  ([#3126](https://github.com/NVIDIA-NeMo/Automodel/pull/3126),
  [#3150](https://github.com/NVIDIA-NeMo/Automodel/pull/3150),
  [#3176](https://github.com/NVIDIA-NeMo/Automodel/pull/3176),
  [#3470](https://github.com/NVIDIA-NeMo/Automodel/pull/3470))

### Checkpointing

- **Preemption checkpointing.** Introduces `step_scheduler.preemption_signal`, which watches one or
  more signals (default `SIGTERM`), gathers the flag across ranks, and saves at the next step
  boundary before exiting cleanly.
  ([docs](https://github.com/NVIDIA-NeMo/Automodel/blob/v0.6.0/docs/guides/checkpointing.mdx),
  [#3007](https://github.com/NVIDIA-NeMo/Automodel/pull/3007))

- **Cloud checkpoint directories.** Accepts `msc://` paths for sharded DCP state; cloud roots
  require `save_consolidated: false`, reject `max_recent_checkpoints`, and keep RNG, dataloader, and
  pointer files local. ([#1709](https://github.com/NVIDIA-NeMo/Automodel/pull/1709))

- **Retention and interrupted saves.** Prunes older directories through `max_recent_checkpoints`,
  and marks in-progress directories until every component is published so resume falls back instead
  of hanging all ranks. ([#2416](https://github.com/NVIDIA-NeMo/Automodel/pull/2416),
  [#3261](https://github.com/NVIDIA-NeMo/Automodel/pull/3261))

- **Async consolidation and new knobs.** Runs consolidated safetensors export through the same
  all-rank consolidation as synchronous mode on a background thread, and adds `cpu_offload`,
  `wait_for_staging`, and `consolidation_timeout_minutes`.
  ([#3108](https://github.com/NVIDIA-NeMo/Automodel/pull/3108),
  [#3125](https://github.com/NVIDIA-NeMo/Automodel/pull/3125),
  [#3130](https://github.com/NVIDIA-NeMo/Automodel/pull/3130),
  [#3131](https://github.com/NVIDIA-NeMo/Automodel/pull/3131))

- **torchsave export to Hugging Face.** Adds `scripts/export_llm_dcp_to_hf.py`, which rebuilds the
  original topology from the checkpoint's recorded `config.yaml` and dispatches the LLM or VLM
  recipe named there, so a VLM checkpoint keeps its vision tower.
  ([#2487](https://github.com/NVIDIA-NeMo/Automodel/pull/2487))

- **Export fidelity and safety.** Keeps fp32 parameters fp32 even under an explicit `cast_dtype`,
  writes safetensors without append, retains later-stage keys in pipeline-parallel consolidation,
  and loads auxiliary `torch.save` state with `weights_only=True`.
  ([#2627](https://github.com/NVIDIA-NeMo/Automodel/pull/2627),
  [#3193](https://github.com/NVIDIA-NeMo/Automodel/pull/3193),
  [#3240](https://github.com/NVIDIA-NeMo/Automodel/pull/3240),
  [#3248](https://github.com/NVIDIA-NeMo/Automodel/pull/3248))

- **Per-global-rank RNG state.** Saves and restores RNG state per global rank rather than per
  data-parallel rank, so tensor- and pipeline-parallel peers keep distinct streams across a resume.
  ([#3437](https://github.com/NVIDIA-NeMo/Automodel/pull/3437))

- **Tied-embedding guards.** Declares a `TieSupport` policy per model class and rejects an
  unsupported `tie_word_embeddings` value.
  ([#2805](https://github.com/NVIDIA-NeMo/Automodel/pull/2805),
  [#2896](https://github.com/NVIDIA-NeMo/Automodel/pull/2896),
  [#2998](https://github.com/NVIDIA-NeMo/Automodel/pull/2998))

- **Chat-template masking and pre-tokenization.** Validates prefix-built answer-only masks against
  the full-conversation render, keeps `system` turns in the ShareGPT converter, and adds

  ([#3024](https://github.com/NVIDIA-NeMo/Automodel/pull/3024),

### Breaking Changes

- `tie_word_embeddings` is validated per model family and raises instead of leaving a randomly
  initialized `lm_head`. ([#2805](https://github.com/NVIDIA-NeMo/Automodel/pull/2805),
  [#2896](https://github.com/NVIDIA-NeMo/Automodel/pull/2896),
  [#2998](https://github.com/NVIDIA-NeMo/Automodel/pull/2998))

- Tokenizer BOS/EOS insertion is opt-in; set `add_bos_token` / `add_eos_token` to keep the previous
  tokenization. ([#3337](https://github.com/NVIDIA-NeMo/Automodel/pull/3337))

- Multi-turn masking raises on chat templates that rewrite earlier turns; affected templates must
  carry `{% generation %}` blocks. ([#3024](https://github.com/NVIDIA-NeMo/Automodel/pull/3024),
  [#3051](https://github.com/NVIDIA-NeMo/Automodel/pull/3051))

- Unrecognized keys under `dataloader:` or on a typed dataset config now raise instead of being
  silently forwarded. ([#2390](https://github.com/NVIDIA-NeMo/Automodel/pull/2390))

- DFlash requires an explicit `mask_token_id`, and `loss_decay_gamma` defaults to 7.0.
  ([#2461](https://github.com/NVIDIA-NeMo/Automodel/pull/2461),
  [#2908](https://github.com/NVIDIA-NeMo/Automodel/pull/2908))

- `BaichuanForCausalLM`, `Qwen2ForCausalLM`, and `KimiVLForConditionalGeneration` are deprecated and
  scheduled for removal in 26.10. ([#2807](https://github.com/NVIDIA-NeMo/Automodel/pull/2807),
  [#2884](https://github.com/NVIDIA-NeMo/Automodel/pull/2884))

### Agent SFT and Speculative Decoding

#### Agent SFT

- The agent-chat data adapter accepts ChatML messages and ShareGPT
  conversations, merges consecutive tool calls, pairs tool responses to call
  IDs, and supervises assistant content and tool-call arguments.
- `train_on_last_turn_only` masks every earlier assistant response and trains
  only on the final assistant turn.
- `reasoning_content` is preserved during data conversion;
  `mask_reasoning_content` can include the trace in the prompt while excluding
  it from loss.
- Generation-based tool-call evaluation reports call presence, tool-name
  accuracy, JSON validity, argument precision/recall, and exact argument match.

#### Speculative Decoding

- EAGLE-1/2 recipes support Llama, Phi, Qwen3, and Qwen3-MoE targets. EAGLE-3
  adds GPT-OSS, and EAGLE-3.1 recipes cover Llama targets.
- A remote target server/client path can train a draft model while target
  supervision runs on a separate GPU.
- P-EAGLE `sequence_partitions` splits a long-context draft step into
  loss-equivalent segments to reduce activation memory.
- Packed variable-length training uses block-causal attention and controls to
  keep, save, or mask target-model reasoning traces.
- Performance tools include SGLang acceptance/speedup benchmarking, offline
  target-output caching, and a fused Triton soft-target cross-entropy kernel
  that avoids allocating a full fp32 log-probability tensor.
