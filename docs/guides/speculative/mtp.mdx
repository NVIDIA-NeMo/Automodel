This guide shows you how to fine-tune a model's existing **Multi-Token
Prediction (MTP)** head to improve its self-speculative accept length on a
target domain, using [NeMo AutoModel](https://github.com/NVIDIA-NeMo/Automodel).

## What is MTP Fine-Tuning?

Several model families ship a native MTP head: extra decoder depths that each
predict one additional future token beyond the main head, trained jointly with
the main next-token loss. At inference, an engine can use those depths to
propose several tokens per verification step, the same way a separate draft
model does for EAGLE or DFlash.

MTP fine-tuning is **not** a separate draft model or recipe. It reuses the
standard `TrainFinetuneRecipeForNextTokenPrediction` recipe, which already
computes the MTP auxiliary loss whenever the loaded model's MTP head is
enabled. Fine-tuning just the MTP head for a new domain is a matter of freezing
everything else and continuing training.

A model with no native MTP head can still get this benefit: see
[Gated-LoRA MTP for Models without a Native MTP Head](#gated-lora-mtp-for-models-without-a-native-mtp-head)
below.

## Supported Models

Training the MTP loss works for any model whose `NeMoAuto*` class reports
`model.supports.mtp_enabled`, including the Qwen3.5 (dense and MoE),
nemotron_v3, step3p7, minimax_m3_vl, deepseek_v4, GLM-5.2, and nemotron_omni
families.

The `val_mtp_tau_sim` accept-length metric below needs more than that: the
model's forward must actually produce MTP outputs during `model.eval()`.
Every family gates MTP computation on `self.training`; today only
`nemotron_v3` (and `nemotron_omni`, which wraps it) additionally exposes
`compute_mtp_in_eval` to opt back in during validation, which the recipe
toggles on automatically. Other families train the MTP loss normally but will
not report `val_mtp_tau_sim` until they add the same hook.

## Freeze Everything but MTP

Add a `freeze_config` block that freezes every module, then unfreezes the MTP
block:

```yaml
freeze_config:
  freeze_modules:
  - glob: "*"
  unfreeze_modules:
  - glob: "*mtp*"
```

`unfreeze_modules` wins over `freeze_modules` on overlap, so only the MTP
submodule's parameters remain trainable. Combine this with any dataset and
optimizer configuration you would use for normal fine-tuning.

## Accept-Length Metric

Validation reports `val_mtp_tau_sim`: the expected self-speculative accept
length under teacher-forced decoding, using the same `tau_sim` convention the
EAGLE-3 recipe already reports for its draft, computed here with no extra
model forward pass. A draft depth is counted as accepted when its argmax
agrees with the **model's own main-head greedy prediction** on the same
teacher-forced context (the actual verifier in self-speculative decoding),
not when it agrees with the dataset label. Those two can disagree whenever
the main head itself is imperfect, so matching the label is not the same
thing as being accepted.
Interpret the value as follows:

- A value near `1.0` means the MTP head's drafts rarely agree with what the
  model's own main head would have produced.
- A value approaching `1 + num_mtp_layers` means every MTP depth is being
  accepted on the validation set.

`val_mtp_tau_sim` only appears when the model supports eval-time MTP (see
[Supported Models](#supported-models)) and a
`validation_dataset` or `validation_dataloader` is configured; it is a pure
diagnostic and does not affect training. It is currently only computed on the
non-context-parallel path.

See [`examples/llm_finetune/mtp_finetune/`](https://github.com/NVIDIA-NeMo/Automodel/tree/main/examples/llm_finetune/mtp_finetune)


## Gated-LoRA MTP for Models without a Native MTP Head

A model with no MTP layers can still be trained for self-speculative decoding,
following [Your LLM Knows the Future](https://arxiv.org/abs/2507.11851). A
`gated_mtp:` block lists one mask token id per MTP depth:

```yaml
gated_mtp:
  mask_token_ids: [151700, 151701, 151702]
```

The dense layout computes one block of mask tokens per clean position. A LoRA
adapter is active only on those masks, and clean queries never attend mask keys.
The clean decoder path stays frozen during training. A shared sampler implements
Section 2.3's two `Linear -> SiLU -> LayerNorm` blocks and projects their output
through the frozen LM head. Depth one starts from the base NTP prediction;
later depths use the preceding sampler prediction. There is no residual
connection or zero-initialized projection in this sampler.

Select the paper's Section 2.5 objective explicitly:

```yaml
gated_mtp:
  mask_token_ids: [151700, 151701, 151702]
  objective: paper
```

It trains base-head CE and sampler-head CE over supervised clean and mask
positions, plus latent consistency MSE toward detached clean hidden states.
Masks after unsupervised anchors do not contribute loss. CE is averaged over
both kinds of positions; consistency first averages matching masks for each
clean target, then averages over supervised clean positions. Samples are
averaged across the full accumulation window, including a partial final window.
`gated_mtp.scaling_factor` scales this complete objective (default `1.0`).
Do not combine it with `mtp.distillation_mode: soft`.

```bash
automodel examples/llm_finetune/mtp_finetune/qwen3_0p6b_gated_lora_mtp.yaml --nproc-per-node 1
```

The 0.6B example is a small validation setup. The
`qwen3_4b_gated_lora_mtp_paper.yaml` example uses eight depths, LoRA rank 128,
AdamW at `2e-4`, 5,000 warmup steps, and 50,000 updates. A single GPU accumulates
an effective batch of eight. Qwen3-4B, Dolly data, sequence length 512, and one
GPU are adaptations; this does not reproduce the paper's speedup experiments.

For compatibility, omitting `objective` retains `objective: mtp`: the existing
hard-MTP CE baseline (without a sampler), or experimental soft distillation
when `mtp.distillation_mode: soft` is supplied. The hard baseline supports
FSDP2/HSDP and DDP. The paper objective and soft sampler currently support only
one GPU because the sampler is attached after the base model is sharded.
All variants require `flex_attention`, `sdpa`, or `eager`, and exclude tensor,
context, and pipeline parallelism, packed sequences, DoRA, sliding-window
attention, and a LoRA-adapted LM head. The paper objective additionally requires
`MaskedCrossEntropy` and excludes domain-mixture loss weights.

Validation reports frozen-base CE and the sampler's teacher-forced prefix-hit
metric `val_mtp_tau_sim`; validation CE does not measure sampler training loss.
The metric is a proxy for acceptance, not an end-to-end generation benchmark.

Mask ids reuse reserved vocabulary rows. Setup deterministically randomizes
those input rows and freezes them. With tied embeddings this also rewrites the
corresponding output rows, changing mask-token logits and the softmax
normalizer: exact distribution parity with the untouched checkpoint is not
guaranteed. The gated path still preserves the clean distribution of this
initialized verifier, provided clean inputs do not contain the reserved ids.

PEFT checkpoints save LoRA and sampler tensors, but not the frozen randomized
mask rows. An external loader must recreate those rows with the same seed and
load the sampler explicitly. Start a new training run for this sampler:
checkpoints from the former zero-initialized residual sampler have different
semantics and must not be resumed as paper-sampler checkpoints.
