**A guide for training a DFlash speculative-decoding drafter to accelerate LLM
inference with [NeMo AutoModel](https://github.com/NVIDIA-NeMo/Automodel).**

---

## What Is DFlash?

DFlash is a *block-parallel* drafter. Where an autoregressive drafter proposes
one token at a time, DFlash proposes an entire block of `block_size` tokens in a
single **non-causal** forward pass: the block's first position holds the real
anchor token and the rest are `MASK`, and the draft "denoises" the whole block at
once conditioned on hidden states captured from the frozen target at
`target_layer_ids`. The draft shares and freezes the target's `embed_tokens` and
`lm_head`, training only the draft stack, its feature projection, and its norms.

It follows the same scaffolding as the EAGLE and DSpark recipes: online target
hidden-state capture, gradient accumulation, and consolidated-safetensors
checkpointing.

## Variants

All five share the DFlash backbone, anchor sampling, and block attention mask.
Only the head and the objective differ:

| Variant | What It Adds | Recipe | Example Config |
|---------|--------------|--------|----------------|
| DFlash | the block-parallel baseline | `TrainDFlashRecipe` | `qwen3_dflash.yaml` |
| DFlash 2 | a two-tap in-block convolution around every sublayer, plus a pairwise path selector that walks one coherent path through each position's top-k candidates | `TrainDFlash2Recipe` | `qwen3_dflash2.yaml` |
| DSpine | causal in-block attention plus an adjacent causal injection after every draft layer: each position receives a gated message built from its predecessor's code, and decoding rescores each position's top-k candidates with the exact previously chosen token | `TrainDSpineRecipe` | `qwen3_dspine.yaml`, `qwen3_8_27b_dspine.yaml` |
| Domino | a serial gated recurrent unit (GRU) correction head that refines each block position on the previous ones | `TrainDominoRecipe` | `qwen3_domino.yaml` |
| JetSpec | causal in-block attention plus forward-KL distillation against the target distribution | `TrainJetSpecRecipe` | `jetspec/` |

DFlash 2 keeps drafting in one pass. The convolution and the selector add
parameters inside the stack rather than an autoregressive correction, so it has
its own draft class whose checkpoint layout matches the published DFlash 2
drafters.

DSpine ([Tencent/DSpine](https://github.com/Tencent/DSpine), "Draft in
Parallel, Condition Through Depth: Adjacent Causal Injection for Speculative
Decoding") also drafts in one pass. Because in-block attention is causal, a
message injected at layer `l` reaches the next position at layer `l + 1`, so the
left-to-right dependency unfolds over the draft's depth. Its checkpoint layout
(`architectures: ["DSpineDraftModel"]`, `selected_prefix_*` config keys, and
`selected_prefix_bridge.*` tensors) matches the released
`tencent/Qwen3-8B-DSpine-b16` and `tencent/Qwen3.8-27B-DSpine-b16` drafters, so a
trained draft loads directly into
SGLang with `--speculative-algorithm DSPINE`. DSpine has no in-repo
`spec_generate`.

## Objective

Only block positions `1..block_size-1` are supervised (position 0 is the clean
anchor). Their cross-entropy (CE) is weighted by a position decay
`w_k = exp(-(k-1)/loss_decay_gamma)`, so early positions (the ones a verifier
reaches first) dominate the loss.

Paper `loss_decay_gamma` values track the block size: 7 for `block_size` 16, 5
for 10, and 4 for 8.

Set `loss_type: variable_prefix` to train the Dual Diffusion Speculative Decoding (D2SD) VP-Drafter objective
([arXiv:2606.04446](https://arxiv.org/abs/2606.04446)) instead: each block draws
a visible-prefix length from a truncated geometric prior
(`prefix_weight_base`, default 0.9), only the masked suffix is supervised, and
the decay restarts at the prefix boundary. This matches the regime a drafter
sees when it re-drafts behind a partially accepted block.

DFlash 2 adds one term on top of the block CE, weighted by
`selector_loss_weight`: a cross-entropy over the position's top-k candidates,
scored against the ground-truth predecessor. Positions whose true token missed
the candidate list carry no selector signal and are reported as
`candidate_recall`.

DSpine replaces the plain CE with the objective of the DSpine authors (the
corrected SpecForge objective). Each block is supervised only up to its first
unsupervised token, with the same position decay, and the loss sums three
parts:

- A backbone term that mixes the CE with the full-vocabulary L1 distance to the
  target's next-token distribution, weighted by `distribution_ce_weight` (default
  0.1, the rest going to the L1).
- A refinement term, with the same CE and L1 mix, over each position's
  `refine_top_k` candidates rescored with the true previous token. The CE counts
  only where the label is a candidate; the L1 only where the target puts more
  than `candidate_mass_threshold` of its mass on the candidates.
- An alignment term that pulls every layer's code toward the fixed codebook code
  of the token that position predicts. It is scaled by the detached backbone CE
  and an `alignment_weight` that warms up over `alignment_warmup_steps` (the LR
  warmup when unset).

The sum is divided by the number of sequences (documents, under sequence packing). A curriculum teacher-forces the
predecessor codes of the first `teacher_forcing_layers` layers on a random subset
of blocks, with a probability that is held and then decays to zero over
training. The recipe reports the refined path as `accuracy` and `accept_len`
(what decoding emits) and the backbone's own picks as `base_accuracy` and
`base_accept_len`. One difference from SpecForge: the detached CE that scales the
alignment term is each micro-batch's own, not one all-reduced over ranks and the
accumulation window.

## Data

Use a chat dataset of OpenAI-format `messages` rows. As with the other
speculative recipes, use Open-PerfectBlend prompts with the **responses
regenerated by the target model**. Training is teacher-forced, so regenerate
the responses before training to avoid a mismatch between the training and
inference distributions. Point
`recipe_args.train_data_path` at the regenerated JSONL or a Hugging Face dataset
id.

<Note>
`mask_token_id` has no default and must name a reserved, rarely-used token. Do
not reuse `pad`: it is frequently aliased to `eos`, which conflates the mask
signal with real content and quietly erodes acceptance. The inference runtime
must fill block slots with the same id.

</Note>

## Run It

Example configs live under `examples/speculative/dflash/`.

```bash
torchrun --standalone --nproc_per_node=2 \
  -m nemo_automodel.recipes.speculative_decoding.train_dflash \
  -c examples/speculative/dflash/qwen3_dflash.yaml
```

Swap the module and config to train a variant. For example,
`-m nemo_automodel.recipes.speculative_decoding.train_dflash2 -c examples/speculative/dflash/qwen3_dflash2.yaml`.

Multi-GPU wraps the draft in Distributed Data Parallel (DDP) and replicates
the frozen target. Set
`distributed.tp_size` to shard a large target across ranks
(`qwen3_dflash_tp.yaml`). `distributed.cp_size` enables context parallelism
that cannot be combined with sequence packing or with `tp_size > 1`.

The published drafters diverge from their target in two ways the recipe
reproduces: a sliding window over the context (`draft_sliding_window`, which also
keeps the flex `BlockMask` sparse on long sequences) and a different attention
shape (`draft_num_attention_heads` and the related attention settings). Refer to
`qwen3_8_27b_dflash2.yaml`.

Training logs `train/loss`, `train/accuracy`, and `train/accept_len`. Setting
`recipe_args.val_data_path` adds globally reduced `val_loss`, `val_accuracy`,
and `val_accept_len`. Adding a top-level `wandb:` block uploads all of them.

## Key Config Fields

The following table describes the key config fields:
| Field | Meaning |
|-------|---------|
| `target_model_name_or_path` | frozen target (for example, `Qwen/Qwen3-8B`) |
| `draft_num_hidden_layers` | draft stack depth (paper: 5) |
| `block_size` | tokens drafted in parallel per block (paper: 16) |
| `num_anchors` | blocks sampled per sequence per step |
| `loss_decay_gamma` | block-position decay; `null` disables it |
| `loss_type` | `dflash` (fixed anchor) or `variable_prefix` |
| `target_layer_ids` | target feature layers fed to the draft (defaults to an even spread) |
| `mask_token_id` | reserved token id filling non-anchor block positions (required) |
| `attention_backend` | `flex_attention` (GPU main path) or `sdpa` (portable fallback) |
| `packed_sequence_size` | enables sequence packing when greater than 0 |
| `draft_sliding_window` | bounds how far back a block reads the context; unset attends over the whole prefix |
| `draft_num_attention_heads` / `draft_num_key_value_heads` / `draft_head_dim` | size the draft's attention independently of the target's |
| `output_multiplier` / `final_logit_softcapping` | the target's logit transform, applied in both training and decoding; identity unless set |
| `input_embedding_scale` | scales the embedded draft block; identity unless set |
| `conv_kernel_size` / `conv_group_size` | DFlash 2 convolution taps and channels per dynamic correction |
| `selector_rank` / `selector_top_k` / `selector_loss_weight` | DFlash 2 path-selector width, candidates scored per position, and objective weight |
| `code_size` / `message_size` / `refine_top_k` | DSpine codebook width, injected-message width, and candidates rescored per position (a power of two up to 64) |
| `distribution_ce_weight` / `candidate_mass_threshold` | DSpine CE weight against the L1-to-target term, and the refinement L1's minimum target mass on the candidates |
| `alignment_weight` / `alignment_warmup_steps` | DSpine alignment weight and its warmup (the LR warmup when unset) |
| `teacher_forcing_layers` / `teacher_forcing_probability` / `teacher_forcing_hold_fraction` / `teacher_forcing_zero_fraction` | DSpine curriculum: teacher-forced early layers, starting per-block probability, and the training fractions where it starts decaying and reaches zero |

`spec_generate` accepts `temperature`, `top_p`, and `top_k`. The truncation
applies to the *target's* distribution (the one rejection sampling verifies
against), so sampled decoding stays lossless with respect to whatever sampling
the target would have used on its own. The DFlash 2 evaluations quote acceptance
lengths at temperature 1.0, top-p 0.95, top-k 20.

Supported targets: Qwen3 and Qwen3.5, dense and Mixture-of-Experts (MoE), including the multimodal
`*ForConditionalGeneration` variants such as `Qwen/Qwen3.8-27B`. DFlash and
JetSpec drafts serve on vLLM through its `dflash` method. DSpine drafts serve on
SGLang's `DSPINE` speculative algorithm.
