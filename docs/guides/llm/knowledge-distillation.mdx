This guide walks through fine-tuning a **student** LLM with the help of a
larger **teacher** model using the `kd` (knowledge distillation) recipe.

In particular, we will show how to distill a 3B (`meta-llama/Llama-3.2-3B`) model into a 1B (`meta-llama/Llama-3.2-1B`) model.

## What is Knowledge Distillation?

Knowledge distillation (KD) transfers the *dark knowledge* of a high-capacity
teacher model to a smaller student by minimizing the divergence between their
predicted distributions. The student learns from both the ground-truth labels
(Cross-Entropy loss, **CE**) and the soft targets of the teacher (Kullback-Leibler
loss, **KD**):

$$
  \mathcal{L} = (1-\alpha) \cdot \mathcal{L}_{\mathrm{CE}}(p_s, y)
  + \alpha T^2 \cdot \mathrm{KL}\!\left(p_{t,T} \parallel p_{s,T}\right)
$$

where $\alpha$ is the `kd_ratio`, $T$ is the softmax `temperature`, and $y$
contains the labels. The temperature-scaled teacher and student distributions are

$$
  p_{t,T} = \operatorname{softmax}\!\left(\frac{z_t}{T}\right), \qquad
  p_{s,T} = \operatorname{softmax}\!\left(\frac{z_s}{T}\right).
$$

## Prepare the YAML Config

A ready-to-use example is provided at
`examples/llm_kd/llama3_2/llama3_2_1b_kd.yaml`.  Important sections:

* `model` – the student to be fine-tuned (1 B parameters in the example)
* `teacher_model` – a larger frozen model used for supervision (3 B)
* `kd_ratio` – blend between CE and KD loss
* `temperature` – softens probability distributions before KL-divergence
* `peft` – **optional** LoRA config (commented). Uncomment to train only a
  handful of parameters.

Feel free to tweak these values as required.

### Example YAML

```yaml
# Example config for knowledge distillation fine-tuning
# Run with:
#   automodel examples/llm_kd/llama3_2/llama3_2_1b_kd.yaml

recipe: KnowledgeDistillationRecipeForNextTokenPrediction

step_scheduler:
  global_batch_size: 32
  local_batch_size: 1
  ckpt_every_steps: 200
  val_every_steps: 100  # will run every x number of gradient steps
  num_epochs: 2

dist_env:
  backend: nccl
  timeout_minutes: 1

seed: 1111

# Student
model:
  _target_: nemo_automodel.NeMoAutoModelForCausalLM.from_pretrained
  pretrained_model_name_or_path: meta-llama/Llama-3.2-1B
  torch_dtype: bf16

# Teacher
teacher_model:
  _target_: nemo_automodel.NeMoAutoModelForCausalLM.from_pretrained
  pretrained_model_name_or_path: meta-llama/Llama-3.2-3B
  torch_dtype: bf16

checkpoint:
  enabled: true
  checkpoint_dir: checkpoints/
  model_save_format: safetensors
  save_consolidated: false

distributed:
  strategy: fsdp2
  dp_size: null
  tp_size: 1
  cp_size: 1
  pp_size: 1
  sequence_parallel: false

# PEFT can be enabled by uncommenting below – student weights will remain small
# peft:
#   _target_: nemo_automodel.components._peft.lora.PeftConfig
#   target_modules: '*_proj'
#   dim: 16
#   alpha: 32
#   use_triton: true

loss_fn:
  _target_: nemo_automodel.components.loss.masked_ce.MaskedCrossEntropy

# Knowledge-distillation hyper-params
kd_ratio: 0.5          # 0 → pure CE, 1 → pure KD
kd_loss_fn:
  _target_: nemo_automodel.components.loss.kd_loss.KDLoss
  ignore_index: -100
  temperature: 1.0
  fp32_upcast: true

# Optimizer
optimizer:
  _target_: torch.optim.Adam
  betas: [0.9, 0.999]
  eps: 1e-8
  lr: 1.0e-5
  weight_decay: 0

# Dataset / Dataloader
dataset:
  _target_: nemo_automodel.components.datasets.llm.squad.make_squad_dataset
  dataset_name: rajpurkar/squad
  split: train

dataloader:
  _target_: torchdata.stateful_dataloader.StatefulDataLoader
  collate_fn: nemo_automodel.components.datasets.utils.default_collater
  shuffle: false

validation_dataset:
  _target_: nemo_automodel.components.datasets.llm.hellaswag.HellaSwag
  path_or_dataset: rowan/hellaswag
  split: validation
  num_samples_limit: 64

validation_dataloader:
  _target_: torchdata.stateful_dataloader.StatefulDataLoader
  collate_fn: nemo_automodel.components.datasets.utils.default_collater
```

### Reduce KD Intermediate Memory

Set `kd_loss_fn.chunk_size` to a positive number of valid tokens to bound the
FP32 working set during loss computation:

```yaml
kd_loss_fn:
  _target_: nemo_automodel.components.loss.kd_loss.KDLoss
  temperature: 1.0
  fp32_upcast: true
  chunk_size: 512
```

Each chunk keeps the full vocabulary. With a Python scalar temperature and
multi-chunk logits up to 32 bits, upcasting and temperature scaling happen
inside each chunk. Autograd retains the intermediates needed for backward;
the loss runs once, with no backward recomputation. Token chunks share one
gradient concatenation instead of each materializing a full token-axis gradient.

Smaller chunks reduce the temporary working set and increase the number of
launches. Compare complete training-step memory and time when choosing a size;
teacher and student output logits occupy memory throughout the loss.
The default `chunk_size: 0` disables chunking. Tensor-parallel loss ignores this
setting. Tensor-valued temperatures, logits wider than 32 bits, and a single chunk
covering all valid tokens retain full-token preprocessing.

### Current Constraints

* Pipeline parallelism requires `pp_microbatch_size` to equal `pp_batch_size` so each student microbatch uses the correct teacher logits.
* Student and teacher models must share the same tokenizer for now; support for different tokenizers will be added in the future.

For VLM knowledge distillation, use the `KnowledgeDistillationRecipeForVLM`
recipe and the checked-in
`examples/vlm_kd/qwen3_5/qwen3_5_vl_4b_kd.yaml` config.

## MoE Knowledge Distillation

The following examples use separate, non-overlapping student and teacher GPU
meshes. They are draft configurations tracked in
[issue #3299](https://github.com/NVIDIA-NeMo/Automodel/issues/3299).

| Student | Teacher | GPUs | Example YAML |
| --- | --- | --- | --- |
| Qwen3-4B | Qwen3-30B-A3B | 8: student DP4, teacher DP4/EP4 | [Dense student with MoE teacher](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_kd/qwen3/qwen3_4b_kd_qwen3_30b_a3b_separate_mesh.yaml) |
| Qwen3-30B-A3B | Qwen3-Next-80B-A3B-Instruct | 16: student DP8/EP8, teacher DP8/EP8 | [MoE student with MoE teacher](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_kd/qwen3/qwen3_30b_a3b_kd_qwen3_next_80b_a3b_separate_mesh.yaml) |

Both examples use FSDP2, Transformer Engine attention, FP32 student master
weights with AdamW, and a frozen BF16 teacher. The KD objective uses
`temperature: 1.0` and `kd_ratio: 0.5`.

### Choose the Student and Teacher Meshes

Set `separate_meshes: true` and specify `dp_size` explicitly in both
`distributed` (student) and `teacher_distributed` (teacher). The launch process
count must equal the sum of the two mesh sizes:

```text
student dp_size * tp_size * cp_size * pp_size
+ teacher dp_size * tp_size * cp_size * pp_size
```

`ep_size` partitions experts over each model's DP/TP/CP ranks; it does not add
another factor to the launch process count. Choose an EP degree that divides
both the model's routed-expert count and `dp_size * tp_size * cp_size`.
For each model and pipeline stage:

```text
ep_shard_size = (dp_size * tp_size * cp_size) / ep_size
```

When `ep_shard_size == 1`, expert parameters are not additionally FSDP-sharded,
so an FSDP CPU `offload_policy` does not offload those parameters. Both examples
keep expert weights resident. The separate whole-teacher option,
`offload_teacher_model`, is unsupported with `separate_meshes: true` and must
remain `false`.

### Launch with W&B Logging

Set `WANDB_API_KEY` and `WANDB_ENTITY` in the launch environment. Each YAML
includes an opt-in `wandb` block and logs every optimizer step when enabled.
For the 8-GPU example:

```bash
automodel examples/llm_kd/qwen3/qwen3_4b_kd_qwen3_30b_a3b_separate_mesh.yaml \
  --nproc-per-node 8 --wandb.enable true
```

For the 16-GPU example, run the following on each of two 8-GPU nodes. Set
`NODE_RANK` to `0` or `1` and `MASTER_ADDR` to the first node's hostname:

```bash
torchrun --nnodes 2 --nproc-per-node 8 --node-rank "$NODE_RANK" \
  --master-addr "$MASTER_ADDR" --master-port 29500 \
  nemo_automodel/recipes/llm/kd.py \
  -c examples/llm_kd/qwen3/qwen3_30b_a3b_kd_qwen3_next_80b_a3b_separate_mesh.yaml \
  --wandb.enable true
```

The main student rank prints the W&B run URL. Inspect `loss`, `ce_loss`,
`kd_loss`, and `grad_norm` to verify that optimizer steps complete with finite
values. At `kd_ratio: 0.5`, total loss should equal `0.5 * ce_loss + 0.5 * kd_loss`.
Validation metrics use `val_<dataset_name>/` prefixes, such as
`val_default/ce_loss`, so validation does not overwrite training values at the
same optimizer step.

### Reproduce a Short Validation Run

Add the following overrides to either launch command to run ten optimizer
steps, validate on eight SQuAD examples, and skip checkpoint writes:

```bash
  --step_scheduler.max_steps 10 \
  --checkpoint.enabled false \
  --validation_dataset.limit_dataset_samples 8
```

These overrides retain the full pretrained models, training dataset, sequence
lengths, and global batch sizes (32 for the dense student and 64 for the MoE
student). Short runs check training execution and finite losses and gradients;
they do not establish convergence, output quality, or checkpoint/resume
correctness.

## Checkpoints and Inference

- Checkpoints are written under the directory configured in the `checkpoint.checkpoint_dir` field at every `ckpt_every_steps`.
- The final student model is saved according to the `checkpoint` section (e.g., `model_save_format: safetensors`, consolidated weights if `save_consolidated: final` or `save_consolidated: every`).

The example config saves sharded Safetensors. Consolidate the latest checkpoint
before loading it with the Hugging Face-compatible model API:

```bash
bash checkpoints/LATEST/model/consolidate.sh
```

Then tokenize the prompt, generate token IDs, and decode them:

```python
import torch
from transformers import AutoTokenizer

import nemo_automodel as am

checkpoint = "checkpoints/LATEST/model/consolidated"
tokenizer = AutoTokenizer.from_pretrained(checkpoint)
student = am.NeMoAutoModelForCausalLM.from_pretrained(
    checkpoint,
    force_hf=True,
    attn_implementation="sdpa",
)
student.eval()

inputs = tokenizer("Translate to French: I love coding!", return_tensors="pt").to(student.device)
with torch.inference_mode():
    output_ids = student.generate(**inputs, max_new_tokens=32)

print(tokenizer.decode(output_ids[0], skip_special_tokens=True))
```
