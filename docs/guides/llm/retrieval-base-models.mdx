Use the examples on this page to adapt a language or vision-language checkpoint
for retrieval. The starting checkpoint supplies the backbone weights; training
produces a custom embedding model or reranker for your data.

To find released retrieval checkpoints, refer to [Embedding Models](/model-coverage/embedding-models/overview)
or [Reranking Models](/model-coverage/reranking-models/overview). A shared backbone
does not imply that an example reproduces a released model.

## Before You Begin

Follow the [installation instructions](/get-started/installation) and run commands
from the repository root. The examples use Transformer Engine's `FusedAdam`
optimizer. The Llama 3.2 and Ministral examples enable Liger kernels, and the
Ministral examples also select FlashAttention 2.
Install these dependencies before launching training.

Accept the access terms for the selected Hugging Face checkpoint and authenticate
your environment. Use the [retrieval fine-tuning guide](/recipes-e2e-examples/retrieval-finetune)
for batch sizes, validation, checkpointing, and export. The commands below launch
on 8 GPUs; check memory use for your configuration.

## Train from Llama

The following examples initialize from
[`meta-llama/Llama-3.2-1B`](https://huggingface.co/meta-llama/Llama-3.2-1B).
They adapt the language-model backbone for retrieval with bidirectional attention
and average pooling. They load the configured FEVER and synthetic classification
training sources from Hugging Face.

Choose the task you want to train:

| Output | Starting Checkpoint | Recipe |
| --- | --- | --- |
| Custom text embedding model | `meta-llama/Llama-3.2-1B` | [Bi-encoder YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/retrieval/bi_encoder/llama3_2_1b.yaml) |
| Custom text reranker | `meta-llama/Llama-3.2-1B` | [Cross-encoder YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/retrieval/cross_encoder/llama3_2_1b.yaml) |

Run the command for your task:

```bash
# Train text embeddings.
uv run automodel examples/retrieval/bi_encoder/llama3_2_1b.yaml --nproc-per-node 8

# Train a text reranker.
uv run automodel examples/retrieval/cross_encoder/llama3_2_1b.yaml --nproc-per-node 8
```

These recipes initialize from the Meta checkpoint. They do not load the released
NVIDIA embedding or reranking weights.

### Llama Embed Nemotron 8B Training Example

The [Llama Embed Nemotron 8B](/model-coverage/embedding-models/nvidia/llama-embed-nemotron-8b)
example starts from
[`meta-llama/Llama-3.1-8B`](https://huggingface.co/meta-llama/Llama-3.1-8B)
and trains on the configured subsets of
[`nvidia/embed-nemotron-dataset-v1`](https://huggingface.co/datasets/nvidia/embed-nemotron-dataset-v1).
Prepare its local data files before launching the
[training YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/retrieval/bi_encoder/llama_embed_nemotron_8b/llama_embed_nemotron_8b.yaml):

```bash
uv run python examples/retrieval/bi_encoder/llama_embed_nemotron_8b/data_preparation.py \
  --download-path ./embed_nemotron_dataset_v1

uv run automodel \
  examples/retrieval/bi_encoder/llama_embed_nemotron_8b/llama_embed_nemotron_8b.yaml \
  --nproc-per-node 8
```

This workflow trains from base weights. Continuing training from the released
NVIDIA checkpoint is a different initialization.

## Train from Ministral

The examples below initialize from
[`mistralai/Ministral-3-3B-Instruct-2512-BF16`](https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512-BF16).
This vision-language checkpoint combines a Ministral language model with a
Pixtral vision encoder. The text example extracts the language model; the
multimodal examples retain the vision encoder.

Choose an example according to your document inputs:

| Output | Backbone Selection | Recipe |
| --- | --- | --- |
| Custom text embedding model | `extract_submodel: language_model` | [Text embedding YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/retrieval/bi_encoder/ministral3_3b_instruct.yaml) |
| Custom multimodal embedding model | Language and vision components | [Multimodal embedding YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/retrieval/bi_encoder/mistral3_vl_embedding.yaml) |
| Custom multimodal reranker | Language and vision components with a scoring head | [Multimodal reranking YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/retrieval/cross_encoder/mistral3_vl_reranker.yaml) |

The text example uses the configured Hugging Face retrieval datasets. Launch it
from the repository root:

```bash
uv run automodel examples/retrieval/bi_encoder/ministral3_3b_instruct.yaml --nproc-per-node 8
```

### Prepare Multimodal Data

Use the [corpus-ID JSON format](/datasets/retrieval-dataset#corpus-id-based-json)
to associate queries with positive and negative document IDs. Include the
referenced corpus and its `merlin_metadata.json` file, with a corpus class that
matches your document format.

In the selected YAML, replace `dataset.data_dir_list[0].path` with your training
JSON path. `<DATASETS_PATH>/retrieval/train.json` is a placeholder. Both multimodal
examples set `use_text_in_document: true`, so image documents include available
companion text. Keep document inputs consistent across mining, training, and
evaluation.

After preparing the data, run the command for your task:

```bash
# Train multimodal embeddings.
uv run automodel examples/retrieval/bi_encoder/mistral3_vl_embedding.yaml --nproc-per-node 8

# Train a multimodal reranker.
uv run automodel examples/retrieval/cross_encoder/mistral3_vl_reranker.yaml --nproc-per-node 8
```

The reranker projects and scales scores in FP32, including under BF16 autocast.
Its recipe computes cross entropy in FP32. Keep the top-level `temperature: 1.0`
when using a non-unit `model.temperature`; setup rejects two active temperature
sources.

To train only the projector and, for reranking, the scoring head, configure tower
freezing at the recipe's top level:

```yaml
freeze_config:
  freeze_vision_tower: true
  freeze_language_model: true
```

## Backbone Reference

The wrappers select the implementation according to the checkpoint's model type
and the requested task:

| Checkpoint Model Type | Embedding Implementation | Reranking Implementation |
| --- | --- | --- |
| `llama`, `llama_bidirec` | `LlamaBidirectionalModel` | `LlamaBidirectionalForSequenceClassification` |
| `ministral3` | Hugging Face `Ministral3Model` | Hugging Face `Ministral3ForSequenceClassification` |
| `mistral3` with a Ministral3 text tower | `Mistral3BidirectionalModel` | `Mistral3VLBidirectionalForSequenceClassification` |
| `ministral3_bidirec` | Legacy `Ministral3BidirectionalModel` | Unsupported by the custom retrieval registry |

For checkpoint variants and language or vision-language training, refer to the
[Llama coverage](/model-coverage/large-language-models/meta) and
[Ministral coverage](/model-coverage/vision-language-models/mistralai/Ministral-3-3B-Instruct-2512)
pages. The [base](https://huggingface.co/mistralai/Ministral-3-3B-Base-2512) and
[instruct](https://huggingface.co/mistralai/Ministral-3-3B-Instruct-2512) variants
are separate initialization choices from the BF16 instruct checkpoint used above.

Refer to the [retrieval fine-tuning guide](/recipes-e2e-examples/retrieval-finetune#choose-a-recipe)
for attention selection, Hugging Face fallback behavior, and text-tower extraction.

For single-vector embeddings, the bi-encoder wrapper supports these pooling modes:

| Mode | Behavior |
| --- | --- |
| `avg` | Average non-padding token hidden states. |
| `cls` | Select the first token hidden state. |
| `last` | Select the last non-padding token hidden state. |
| `weighted_avg` | Sum non-padding token hidden states. |

Preserve the checkpoint's pooling, normalization, prompts, and preprocessing when
continuing training or building an index. Changing the attention policy changes
the embeddings and requires regenerating stored corpus embeddings.
