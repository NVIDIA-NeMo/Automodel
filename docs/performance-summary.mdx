### Measurement Method

For the new language and vision-language rows, step time is reconstructed from each logged pair of `num_tokens_per_step` and `tps`. Mean step time is the arithmetic mean of those reconstructed times. Tokens/sec/GPU is the total logged tokens divided by total reconstructed time and the physical GPU count. This preserves the source run's token-count and timing semantics, including any overhead in its timer. In particular, the MedPix rows are not full-length synthetic sequence benchmarks.

The aggregation uses logged training steps 10-99 inclusive, with these exceptions:

- Qwen3.8-Flash-Next uses the run's synchronized benchmark summary: 30 measured steps after 20 warmup steps. Its token rate counts label tokens. Model TFLOPs/sec/GPU is derived from the reported 8.7815% MFU and the H100 BF16 peak of 989 TFLOPs/sec.
- MiMo-V2.5-Pro uses steps 10-19 from a short 20-update run that also performs validation. Its reconstructed time can include validation overhead.
- Nemotron-3.5-Lightning uses steps 10-299.
- Kimi-Linear uses steps 10-49.

Image-generation rates are calculated as `GBS / step_time / physical_GPU_count`. Language and image-generation rates use different units and should not be compared.

For the new rows, `NR` means not recorded or not verified; `-` means not applicable. FSDP2 is the recorded strategy, but its shard degree was not verified, so the numeric FSDP column is `NR`. GA is derived as `GBS / (LBS * DP)`, where `DP = #GPUs / (TP * PP * CP)`; EP overlaps these mesh axes and is not an additional divisor. MBS is the recorded pipeline micro-batch size for PP runs and equals LBS otherwise. Unverified model FLOP estimates are left as `NR`.

## Glossary

- **MFU**: Model FLOPs Utilization - ratio of achieved compute to peak hardware capability
- **TP**: Tensor Parallelism - splits individual layers across GPUs
- **PP**: Pipeline Parallelism - splits model layers into stages
- **CP**: Context Parallelism - splits the sequence across GPUs
- **FSDP**: Fully Sharded Data Parallelism - the table column gives the shard degree when verified
- **EP**: Expert Parallelism - distributes MoE experts across GPUs
- **DP**: Data Parallelism - replicates model and splits data
- **VP**: Virtual Pipeline - number of pipeline stages per GPU for interleaving
- **MBS**: Micro-Batch Size - size of one forward pass in pipeline
- **LBS**: Local Batch Size - size of one step per GPU
- **GBS**: Global Batch Size - total batch size across all GPUs
- **GA**: Gradient Accumulation - number of local-batches before optimizer step
- **TE**: Transformer Engine kernel optimizations - RMSNorm, Linear and DotProductAttention
- **DeepEP**: Deep Expert Parallelism - advanced EP routing for MoE models
- **FlexAttn**: PyTorch's [Flex Attention](https://docs.pytorch.org/docs/stable/nn.attention.flex_attention.html)

The following assumptions apply to the pre-training and LoRA benchmark tables at the top of this page. The new-model tables use the measurement methods and workloads documented in their own section.

- These benchmarks use mock data for consistent performance measurement.
- Fake balanced gate is enabled to simulate ideal expert routing.
- No gradient clipping applied for pure performance measurement.
- MFU calculated using peak TFLOPs for the system (989 for BF16 H100).
- Step times include forward and backward passes and optimizer step for the global batch.
