## Fine-Tuning Performance

Compute values are model TFLOPs/sec/GPU. A star (<sup>&#42;</sup>) marks estimates calculated from recorded throughput; see the [estimate notes](#estimate-notes) at the end of this page. GLM-5.3, Kimi-Linear, Nemotron-3.5-Lightning, and Laguna retain recorded model FLOPs recovered from MFU using the original reference peaks, rather than current device defaults.

Compute estimates use the same measurement windows as token throughput: steps 10-99, except MiMo-V2.5-Pro (10-19), Kimi-Linear (10-49), Nemotron-3.5-Lightning (10-299), and Qwen3.5-4B (3-5).

## Glossary

- **NR**: Not recorded or not verified
- **MFU**: Model FLOPs Utilization - ratio of achieved compute to peak hardware capability
- **TP**: Tensor Parallelism - splits individual layers across GPUs
- **PP**: Pipeline Parallelism - splits model layers into stages
- **CP**: Context Parallelism - splits the sequence across GPUs
- **FSDP**: Fully Sharded Data Parallelism - the table column gives the shard degree when verified
- **EP**: Expert Parallelism - distributes MoE experts across GPUs
- **DP**: Data Parallelism - replicates model and splits data
- **VP**: Virtual Pipeline - number of pipeline stages per GPU for interleaving
- **MBS**: Micro-Batch Size - size of one forward pass in pipeline
- **LBS**: Local Batch Size - size of one step per GPU
- **GBS**: Global Batch Size - total batch size across all GPUs
- **GA**: Gradient Accumulation - number of local-batches before optimizer step
- **TE**: Transformer Engine kernel optimizations - RMSNorm, Linear and DotProductAttention
- **[DeepEP](https://github.com/deepseek-ai/DeepEP)**: Expert-parallel communication library for MoE token dispatch and combine
- **FlexAttn**: PyTorch's [Flex Attention](https://docs.pytorch.org/docs/stable/nn.attention.flex_attention.html)

## Estimate Notes

\* **Estimated TFLOPs/sec/GPU:** Starred values are calculated from recorded input tokens/sec/GPU and nominal training FLOPs per token. They exclude activation recomputation, padding, communication, and optimizer work.

For Qwen3.8-27B, GLM-5.3-Flash, DeepSeek-V4-Flash-Vision-Exp, DeepSeek-V4.1-Flash, and Qwen3.5-4B, the estimates cover the **language backbone only** and exclude vision-encoder and projector work. These MedPix workloads include images; the estimate's scope does not mean that training used text-only data. Nemotron-3.5-Super-VL's Tulu-3 workload is itself text-only.

The backfilled text estimates use `TFLOPs/sec/GPU = FLOPs/token * tokens/sec/GPU / 1e12`, counting activated MoE experts rather than all experts. Estimates that depend on document length use the arithmetic midpoints of their FLOPs ranges, rounded to at most two decimal places. The underlying ranges account for unknown document lengths, from one token to the recipe cap (2K for GLM-5.3-Flash; 4K for DeepSeek-V4/V4.1). Qwen3.8-27B instead uses the largest recorded global input-token count, 5,672, as a conservative sequence-length cap. These are nominal model-work estimates, not measured hardware FLOPs.

- Qwen3.8-27B uses the [hybrid GDN/attention formula](https://github.com/NVIDIA-NeMo/Automodel/blob/024f2eff3e152f6b0ad702eb18b5298a7c9d69e9/nemo_automodel/components/utils/flops_utils.py), including the run's one enabled MTP layer.
- GLM-5.3-Flash uses its [KDA/MLA, dense/MoE, and mHC projection shapes](https://github.com/NVIDIA-NeMo/Automodel/blob/024f2eff3e152f6b0ad702eb18b5298a7c9d69e9/nemo_automodel/components/models/glm5_next/layers.py), the [chunk-64 KDA FLOPs formula](https://github.com/NVIDIA-NeMo/Automodel/blob/024f2eff3e152f6b0ad702eb18b5298a7c9d69e9/nemo_automodel/components/utils/flops_utils.py), causal attention, and forward-only frozen KPool indexing. MTP is disabled.
- DeepSeek-V4 and V4.1 use their [V4 text formula](https://github.com/NVIDIA-NeMo/Automodel/blob/024f2eff3e152f6b0ad702eb18b5298a7c9d69e9/nemo_automodel/components/models/deepseek_v4/flops.py) and [V4.1 text formula](https://github.com/NVIDIA-NeMo/Automodel/blob/024f2eff3e152f6b0ad702eb18b5298a7c9d69e9/nemo_automodel/components/utils/flops_utils.py), with MTP disabled.
- Nemotron-3.5-Super-VL uses the rough `6N` training-FLOPs-per-token approximation, where `N` is the number of active parameters per token (approximately `2N` for forward and `4N` for backward): `6 * 13e9 * 230.26 / 1e12 ~= 18`, using the approximately 13B active parameters reported for the measured checkpoint in its [source PR](https://github.com/NVIDIA-NeMo/Automodel/pull/3801). Its original full configuration is unavailable; this approximation omits attention BMMs and SSM recurrence and is less precise than the model-specific estimates.

MiMo estimates use the midpoints of ranges calculated from [model-specific nominal text FLOPs](https://github.com/NVIDIA-NeMo/Automodel/blob/1bf1e134327e27fcdef25f3dd49d275e77dfd875/nemo_automodel/components/models/mimo_v2_flash/flops.py) times recorded input tokens/sec/GPU, replacing the incorrect generic-formula MFU. MiMo-V2.6 endpoints assume document lengths from one token to the pack limit (4K/64K); individual packed lengths were not retained. MiMo-V2.5-Pro uses lengths from one token to 11,362, the largest recorded global input-token count in steps 10-19, as a conservative cap on any individual sequence.

Qwen3.5-4B's ~61.5 TFLOPs/sec/GPU estimate covers the text backbone only using the [hybrid GDN/attention formula](https://github.com/NVIDIA-NeMo/Automodel/blob/c9480acf208a940bf719a74316bd2e90f805264c/nemo_automodel/components/utils/flops_utils.py) and document lengths from one token to 16K; it excludes vision work.
