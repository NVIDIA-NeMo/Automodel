## Introduction

Reranking models use cross-encoders to score a query-document pair jointly. They are typically used after an embedding model has produced an initial candidate set. NeMo AutoModel supports optimized bidirectional Llama rerankers and a causal Qwen3 reranker that scores with a yes or no decision at the final token, and falls back to Hugging Face `AutoModelForSequenceClassification` for other architectures.

For first-stage dense retrieval, see [Embedding Models](/model-coverage/embedding-models/overview).

## Train from a Base Model

To create a custom reranker from Llama or Ministral weights, follow
[Train Retrieval Models from Base Checkpoints](/recipes-e2e-examples/retrieval-base-models).
These examples train a scoring model from a language or vision-language checkpoint.
They do not imply reproduction of a named, released reranker.

The retrieval implementations include `LlamaBidirectionalForSequenceClassification`
for Llama scoring, `Mistral3VLBidirectionalForSequenceClassification` for multimodal
Mistral3 scoring, and `Qwen3RerankerForCausalReranking` for causal yes/no scoring.
Refer to the [backbone reference](/recipes-e2e-examples/retrieval-base-models#backbone-reference)
and [Qwen model page](/model-coverage/reranking-models/qwen/Qwen3-Reranker-4B)
for task-specific behavior.

## Supported Workflows

- **Fine-tuning (Cross-Encoder):** Cross-entropy training on query-document pairs to produce rerankers
- **LoRA and PEFT:** Parameter-efficient fine-tuning for reranking backbones

## Dataset

Retrieval fine-tuning requires query-document pairs: each example is a query paired with one positive document and one or more negative documents. Both inline JSONL and corpus ID-based JSON formats are supported. See the [Retrieval Dataset](/datasets/retrieval-dataset) guide.
