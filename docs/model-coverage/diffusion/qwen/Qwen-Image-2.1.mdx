[Qwen-Image-2.1](https://huggingface.co/Qwen/Qwen-Image-2.1) is Alibaba Cloud's flow-matching text-to-image model. NeMo AutoModel supports full-parameter and LoRA fine-tuning of Qwen-Image-2.1.

## Quick Start

Follow the [installation instructions](/get-started/installation) and complete the [recipe setup](#recipe-setup). From the repository root, launch full-parameter fine-tuning on one node with 8 GPUs:

```bash
uv run --extra all torchrun --nproc-per-node=8 \
  examples/diffusion/finetune/finetune.py \
  -c examples/diffusion/finetune/qwen_image_21_t2i_flow.yaml
```

## Model Context

Qwen-Image-2.1 generates images from text using a diffusion transformer with 7.12B parameters. This count excludes the text encoder and VAE.

| Property | Value |
|---|---|
| **Task** | Text-to-Image |
| **Architecture** | Diffusion Transformer (Flow Matching) |
| **HF Org** | [Qwen](https://huggingface.co/Qwen) |
| Parameters | 7.12B diffusion-transformer parameters; excludes the text encoder and VAE |
| Transformer Blocks | 32 |
| Hidden Size | 4,096 |
| Attention | 32 attention heads |

### Overview

Qwen-Image-2.1 is a 7B single-stream, block-causal DiT conditioned on Qwen3-VL hidden states. It uses a 64-channel RGBA VAE with 16x spatial compression, so image sides must be multiples of 32 pixels. It requires a Diffusers build that provides `QwenImage21Pipeline`.

### Prepare the Dataset

Cache VAE latents and Qwen3-VL prompt embeddings with the `qwen_image_21` processor. RGB images receive an opaque alpha channel before VAE encoding:

```bash
uv run --extra all --extra diffusion-media python -m tools.diffusion.preprocessing_multiprocess image \
  --dataset_name lambdalabs/naruto-blip-captions \
  --dataset_media_column image --dataset_caption_column text \
  --processor qwen_image_21 \
  --resolution_preset 1024p \
  --verify \
  --output_dir /cache/naruto-qwen-image-21
```

### Generate Images

Generate images with the base model:

```bash
uv run --extra all python examples/diffusion/generate/generate.py \
  -c examples/diffusion/generate/configs/generate_qwen_image_21.yaml
```

To use a full fine-tuning checkpoint, add `--model.checkpoint /path/to/checkpoint`. For a LoRA adapter, add `--model.lora_weights /path/to/adapter`, pointing to the directory containing `adapter_config.json` and `adapter_model.safetensors`.

### Fine-Tune the Model

Set `data.dataloader.cache_dir` and `checkpoint.checkpoint_dir`, then launch one FSDP2 rank per GPU:

```bash
uv run --extra all torchrun --nproc-per-node=8 \
  examples/diffusion/finetune/finetune.py \
  -c examples/diffusion/finetune/qwen_image_21_t2i_flow.yaml
```

The `qwen_image_21` adapter supervises only the target-image tokens of the joint text and image sequence. The transformer lays out RoPE positions once per batch. Prompt padding would shift the image positions, so the adapter runs each sample as its own unpadded transformer call and sees the positions of single-prompt inference. Qwen-Image-2.1 is sampled without classifier-free guidance, so the recipes set `cfg_dropout_prob: 0.0`. On 8x H100 80 GB at 1024x1024 with a global batch of 16, the full fine-tune runs at about 1.4 s per step and uses about 60 GB per GPU; LoRA runs at about 1.05 s per step and uses about 56 GB per GPU.

### Recipe Setup

1. Use a Diffusers build that provides `QwenImage21Pipeline`. The full fine-tuning recipe requires Transformer Engine's `FusedAdam` optimizer from the `cuda` extra, which a base install omits. The commands on this page select `all` to include `cuda`, `diffusion`, and `vlm`; preprocessing also selects `diffusion-media` for OpenCV.
2. [Prepare the dataset](#prepare-the-dataset) to cache image latents and prompt embeddings.
3. In the selected fine-tuning recipe, set `data.dataloader.cache_dir` to the preprocessing output directory and `checkpoint.checkpoint_dir` to a writable checkpoint directory. The full fine-tuning recipe uses `fsdp.dp_size: 8`, matching the Quick Start launch.
