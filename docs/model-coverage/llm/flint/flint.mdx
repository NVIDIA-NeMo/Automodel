Flint is a text-only mixture-of-experts causal language model from
RecursiveSI, registered as `FlintForCausalLM` (`model_type: flint`). The BF16
checkpoint is [RecursiveSI/flint](https://huggingface.co/RecursiveSI/flint).

## Model Reference

### Model Architecture

| Property | Value |
| --- | --- |
| Task | Text Generation |
| Architecture | `FlintForCausalLM` |
| Model type | `flint` |
| Layers | 49 |
| Parameters | 39.8B total, about 2.5B active per token |
| Checkpoint | [RecursiveSI/flint](https://huggingface.co/RecursiveSI/flint) |

The checkpoint has 49 layers, hidden size 2,048, vocabulary size 150,144,
32 query heads, four key/value heads, and head dimension 128. Layers 0 and 1
use dense MLPs. The remaining layers use 256 routed experts, top-six routing,
and an ungated shared expert. Routing weights apply after the expert down
projection.

Fourteen layers (0, 1, 5, 9, ..., 45, and 48) use full attention without
positional encoding; the other 35 use sliding-window attention with NeoX RoPE.
The sliding window includes the current token and 512 preceding tokens.
Query/key normalization precedes RoPE. Every attention head has a trainable denominator sink with zero value; the sink is not an
extra input token. The output head is untied. Sinks and head computation
remain FP32, including under BF16 bulk computation. The EOS/padding embedding
row remains trainable: positional masks distinguish padding from real EOS
tokens.

Set `model.config.router_aux_loss_coef: 0.0` explicitly for CE-only training.
The checkpoint's nonzero auxiliary coefficient (`0.0005`) does not specify its
original training objective, so these recipes do not reconstruct that objective.

## Numerical comparison

The released-weight comparison uses the first four layers of the 49-layer
schedule, a seeded 4,096-token input, and every vocabulary entry at every
position. Native loading validates the complete source index and all selected
tensor values. The reference loads literal checkpoint keys separately and
evaluates FP32 PyTorch SDPA without importing native model math.

<Note>
The checkpoint does not provide a Hugging Face modeling implementation. The
reference is an independent test implementation, not an official HF model or
the SGLang serving kit shipped with the checkpoint. Four-layer measurements do not describe
full 49-layer serving numerics.
</Note>

Download `RecursiveSI/flint` to a local directory, then run inside an existing
GPU allocation from the repository root:

```bash
python -m tests.functional_tests.models.flint.run_four_layer_logits \
  --checkpoint /path/to/flint --output /path/to/output/fp32-sdpa \
  --device cuda:0 --attn sdpa --candidate-dtype float32 \
  --load-method from_pretrained
```

Use a separate output directory for the BF16 TE candidate:

```bash
python -m tests.functional_tests.models.flint.run_four_layer_logits \
  --checkpoint /path/to/flint --output /path/to/output/bf16-te \
  --device cuda:0 --attn te --candidate-dtype bfloat16 \
  --residual-dtype fp32 \
  --load-method from_pretrained
```

For the FP32-body/FP16-TE-attention candidate, use:

```bash
python -m tests.functional_tests.models.flint.run_four_layer_logits \
  --checkpoint /path/to/flint --output /path/to/output/fp32-te-fp16-attention \
  --device cuda:0 --attn te --candidate-dtype float32 \
  --residual-dtype fp32 --attention-compute-dtype fp16 \
  --load-method from_pretrained
```

This selects `model.config.attention_compute_dtype: fp16`. It casts normalized,
rotated Q/K/V at the TE boundary and restores FP32 before the output
projection; projection computation stays FP32. The default `null` policy
leaves BF16 computation unchanged. Tiny-gradient GPU tests observe FP16
underflow without explicit loss scaling, so this option is for comparison and
inference; the training recipes use BF16.

The tool reports mean `KL(reference || candidate)` computed with FP32
log-softmax over the full vocabulary, per-position KL percentiles and maximum,
Jensen-Shannon divergence, cosine, absolute logit error, top-one agreement, and
per-layer hidden-state differences, together with a manifest of seeds, input
hashes, source hashes, package versions, dtype, and backend.

Measured first-four-layer results (GB200, Torch 2.13.0a0, TE 2.14.1,
cuDNN 9.23, Transformers 5.18.0; all 1,589 selected source tensors load
bit-identical):

| Candidate | Mean KL | Top-one agreement |
| --- | --- | --- |
| FP32 SDPA | `-1.37e-9` (FP32 roundoff) | 100% |
| BF16 TE, FP32 residual | `2.83e-3` | 97.974% |
| BF16 SDPA, FP32 residual | `2.91e-3` | 98.169% |
| FP32 body, FP16 TE attention | `2.79e-5` | 99.976% |

For the FP32-body/FP16-TE-attention candidate, the maximum absolute logit
error is `4.8910178` and the mean absolute logit error is `0.0071718`.

## Parallelism and backends

Packed examples retain document boundaries, reset position IDs, ignore
padding labels, and shift next-token labels exactly once. Controlled CP
comparisons must reuse the same physical packs, document ordering, real token
count, loss normalization, and expert topology; a topology change must not
silently repack the dataset. THD pipeline execution requires one physical
packed row per microbatch. The source maximum position count is 262,144.

TE context parallelism uses all-to-all communication for the learned sinks.
Both query and key/value head counts must divide evenly across the CP group,
so the four key/value heads permit CP2 or CP4. The sink-only FSDP unit
corrects TE's replicated sink adjoint before gradient clipping.

MagiAttention is the long-context backend for H100 (SM90). It shards the
sequence rather than the attention heads, so its CP size is not bound by the
key/value head count. The H100 recipe trains full 49-layer 128K packs at
TP1/PP1/CP8/EP8 on one 8-GPU node using about 59 GiB per GPU. The Magi path
requires one packed row per microbatch: without PP, set the dataloader
`batch_size` to 1 and use gradient accumulation for larger global batches.

<Warning>
Magi training with learned sinks is not supported on GB200. The pinned Magi
FFA backend requires SM90 hardware, while its FA4 backend
[rejects learned sinks in backward](https://github.com/SandAI-org/MagiAttention/blob/d7ea8afd44c790b65fab68a04a6a0fdd5adbf182/magi_attention/functional/fa4.py#L240).
Use the TE long-context recipe on GB200.
</Warning>
