[Kimi Linear](https://huggingface.co/moonshotai/Kimi-Linear-48B-A3B-Instruct) is a hybrid-attention mixture-of-experts (MoE) language model from Moonshot AI. Most layers use Kimi Delta Attention (KDA), a gated linear-attention variant with a recurrent state, and the remaining layers use full Multi-Head Latent Attention (MLA). NeMo AutoModel ships a native `KimiLinear48BForCausalLM` implementation with expert parallelism, packed sequences, and context parallelism.

Set up NeMo AutoModel with the [latest container](https://catalog.ngc.nvidia.com/orgs/nvidia/containers/nemo-automodel) or follow the [installation instructions](/get-started/installation).

## Quick Start

From the repository root, run this eight-GPU example with the required Flash Linear Attention (`fla`) extra:

```bash
uv run --extra fla automodel --nproc-per-node=8 examples/llm_finetune/kimi/kimi_linear_48b_a3b_hellaswag.yaml
```

## Model Context

Kimi-Linear-48B-A3B-Instruct combines linear attention with MoE layers for text generation. Moonshot AI reports 48B total parameters and 3B active parameters per token.

| Property | Value |
| --- | --- |
| Task | Text Generation (hybrid linear attention, MoE) |
| **Architecture** | `KimiLinear48BForCausalLM` |
| Parameters | 48B total / 3B active |
| Hugging Face Organization | [moonshotai](https://huggingface.co/moonshotai) |
| Decoder Layers | 27 |
| Hidden Size | 2,304 |
| Attention | 32 attention heads / 32 key-value heads |
| Vocabulary Size | 163,840 |
| Experts | 256 routed / 1 shared / 8 selected per token |
| Configured Dtype | `bfloat16` |

- `KimiLinear48BForCausalLM` (`model_type: kimi_linear_48b_a3b`)
- Hybrid attention stack: KDA linear-attention layers interleaved with MLA layers
- MoE feed-forward blocks with sigmoid routing and grouped top-k selection

Moonshot publishes this model and the Kimi K3 text backbone under the same
`model_type: kimi_linear` and the same `architectures: ["KimiLinearForCausalLM"]`, so
neither field identifies the model on its own. NeMo AutoModel gives this implementation a
distinct identity, `kimi_linear_48b_a3b` / `KimiLinear48BForCausalLM`, and leaves
`kimi_linear` to the K3 text config. The example recipes name `KimiLinear48BConfig`
explicitly, which is what a published Moonshot checkpoint needs; checkpoints saved by
NeMo AutoModel already carry the distinct identity and load without that override.

<Note>
Both the [HellaSwag](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_finetune/kimi/kimi_linear_48b_a3b_hellaswag.yaml#L54-L71) and [packed-sequence](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_finetune/kimi/kimi_linear_48b_a3b_longcontext_cp8.yaml#L61-L79) examples load base weights (`load_base_model: true`). They disable checkpoint saving (`checkpoint.enabled: false`), so they do not retain trained weights after the run.
</Note>

### Supported Parallelism

| Feature | Notes |
|---|---|
| Fully Sharded Data Parallel v2 (FSDP2) | Default sharding strategy for the examples in Choose a Workflow |
| Expert parallelism (EP) | Shards the MoE experts across ranks |
| Context parallelism (CP) | Contiguous per-rank sequence shards. KDA passes its recurrent state from rank to rank, and MLA gathers the compressed key-value latent |
| Packed sequences | Document boundaries from `packed_sequence_thd_collater` are honored by both layer types, including under CP |
