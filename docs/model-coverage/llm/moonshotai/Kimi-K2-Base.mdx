[Kimi-K2-Base](https://huggingface.co/moonshotai/Kimi-K2-Base) has a checked-in NeMo AutoModel recipe for benchmarking training on synthetic data. The recipe initializes the model from configuration rather than loading checkpoint weights.
The Hugging Face configuration declares the `DeepseekV3ForCausalLM` architecture.

## Quick Start

This example benchmarks training on synthetic data across 32 nodes with 8 GPUs each. Complete the prerequisites in Model Context, then run the command from the repository root on every node.

```bash
uv run torchrun --nnodes 32 --nproc-per-node 8 \
  --node-rank "$NODE_RANK" --master-addr "$MASTER_ADDR" --master-port 29500 \
  -m nemo_automodel.cli.app examples/llm_benchmark/kimi/kimi_k2_te_deepep.yaml
```

## Model Context

Kimi-K2-Base is used for text generation. Its model size is 1026.47B checkpoint parameters.

| Property | Value |
| --- | --- |
| Task | Text generation |
| **Architecture** | `DeepseekV3ForCausalLM` |
| Parameters | 1026.47B checkpoint parameters |
| Decoder Layers | 61 |
| Hidden Size | 7,168 |
| Attention | 64 attention heads and 64 key-value heads |
| Context Length | 131,072 tokens (checkpoint configuration); 4,096 tokens in the benchmark recipe |
| Vocabulary Size | 163,840 |
| Experts | 384 routed experts and 1 shared expert; 8 routed experts selected per token |
| Configured Dtype | `bfloat16` |

### Configuration

| Setting | Configuration |
| --- | --- |
| Hardware | 8 GPUs per node (launch example) |
| Strategy | FSDP2; `tp_size=1`, `pp_size=8`, `cp_size=1`, `ep_size=32` |
| Nodes | 32 |
| Features | Activation checkpointing (`activation_checkpointing=true`), Transformer Engine, HybridEP (`dispatcher=hybridep`) |
| Advanced | `attn=te`, `linear=te`, `experts=torch_mm`, `dispatcher=hybridep` |

### Workflow Notes

1. Follow the [installation instructions](/get-started/installation). Use the same source checkout and environment on all nodes, with Transformer Engine and HybridEP available.
2. Set `NODE_RANK` to a unique integer from 0 through 31 on each node. Set `MASTER_ADDR` to the rank-0 node's address on every node, reachable on port 29500.

The recipe uses pipeline parallelism (`pp_size=8`) and expert parallelism (`ep_size=32`). It enables synthetic balanced routing (`fake_balanced_gate=true`), runs 30 steps with 10 warmup steps, and disables checkpoint saving. These settings measure benchmark performance; they do not define a fine-tuning workflow.
