[DeepSeek-V4.1 Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash)
uses a 40-layer causal encoder/decoder backbone with 384 routed experts, one
shared expert, and six selected experts per token. Its CSA2 attention shares
compressed KV and index state between Full, Reuse, and Reindex layers.
Single-pass mHC carries four residual streams, and two trainable Engram tables
provide tokenizer-dependent N-gram memory. The approximately 552B backbone is
accompanied by 196B Engram parameters.

| Setting | Value |
|---|---|
| **Architecture** | `DeepseekV41ForCausalLM` |
| Model ID | `deepseek-ai/DeepSeek-V4.1-Flash` |
| Reference revision | `df42c109f1defefcbfcedbe7d905718a12266e40` |
| Configuration | `DeepseekV41Config` with typed `text_config` and `vision_config` |

<Note>
The numerical results below belong to the original implementation at commit
`0d5919a5a506dd35dc4f55769410feb98ae854b8`. Final validation of the current PR
implementation remains pending. The 16-node and 32-node validation runs are
also pending; neither establishes successful resident 100-update training.
</Note>

## Fine-tuning

Both recipes train all 40 text-backbone layers and both Engram tables. Dense
parameters use generic FSDP2; routed experts use the shared AutoModel MoE
implementation with HybridEP dispatch. Engram reuses the Qwen3.8 Flash Next
row-owner embedding and distributes each table across the same world ranks
without a full-table all-gather. Its gradients return to the row owners and
receive the owner divisor once before clipping.

| Recipe | Topology and batch | Optimizer moments and checkpoints |
|---|---|---|
| [HellaSwag EP64](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_finetune/deepseek_v41/deepseek_v41_flash_hellaswag_ep64_16nodes.yaml) | 16 nodes × 4 GB200; EP64, owner64, TP1/PP1/CP1; global batch 64, local batch 1 | BF16 moments; checkpoint saving disabled |
| [HellaSwag EP128](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_finetune/deepseek_v41/deepseek_v41_flash_hellaswag_ep128.yaml) | 32 nodes × 4 GB200; EP128, owner128, TP1/PP1/CP1; global batch 128, local batch 1 | FP32 moments; checkpoints every 50 updates |

Both configurations request 100 updates with validation every 50 updates,
activation checkpointing, and reshard-after-forward. Neither uses gradient
accumulation or an additional expert FSDP shard axis. The EP64 configuration
requests a one-hour allocation and online W&B logging. TE FusedAdam retains
FP32 master-weight precision through int16 remainders for BF16 parameters.
EP64 checkpoint saving is disabled because exporting its BF16 optimizer
moments expands them to FP32 before checkpoint offload; save/resume validation
for this configuration is deferred.

The EP64 allocation must place all 64 ranks in one verified NVLink domain,
with static rank ordering. The earlier resident 16-node run using FP32 moments
completed optimizer update 0 and ran out of memory during the next backward.
The BF16-moment recipe is a new validation configuration, not a demonstrated
memory-fit result.

Both recipes explicitly select `attn: tilelang`, `linear: torch`,
`experts: torch_mm`, and `dispatcher: hybridep`. TileLang and TileKernels are
the optional dependencies already used by DeepSeek V4. Shared MoE combines
routed contributions and the shared-expert output in FP32, then casts once at
the MoE output. The optional `torch_linear` backend uses different projection
and activation arithmetic; its historical exact results do not describe the
selected `torch_mm` backend.

For the EP128 recipe with four GB200 GPUs per node, export this on every node
before launching the training ranks:

```bash
export NUM_OF_HYBRID_EP_RANKS_PER_NVLINK_DOMAIN=4
```

This gives HybridEP equal four-rank, node-local NVLink groups when the
allocation spans partial or unequal NVL72 domains. Every training rank must
inherit it. The EP64 single-domain allocation uses its verified 64-rank domain
instead of this four-rank override.

Set `DS41_CHECKPOINT` to the absolute path of the shared local HF snapshot for
revision `df42c109f1defefcbfcedbe7d905718a12266e40`, using the same directory for
parity and training. Pass both snapshot overrides to the training command:

```bash
--model.config.pretrained_model_name_or_path="$DS41_CHECKPOINT" \
--model.config.name_or_path="$DS41_CHECKPOINT"
```

Text architecture settings belong to the nested `DeepseekV41TextConfig` in
`config.text_config`; vision settings belong to `config.vision_config`.
Engram layers require the checkpoint's fast tokenizer during construction.
Their compressed map and hash buffers are restored after meta materialization.
The enabled layers are selected by `engram_layer_ids`, and their tables are
trainable. There is no separate Engram freezing or KV quantization switch.

FSDP mixed precision must use `param_dtype: bfloat16`, `reduce_dtype: float32`,
`output_dtype: null`, and `cast_forward_inputs: false`. Set
`lm_head_precision: float32`. These settings preserve FP32 mHC coefficients
across module boundaries. The language-model head returns FP32 logits.

The checkpoint adapter decodes the released FP8 dense weights, FP4 experts,
and FP8 Engram tables into trainable parameters. The recipes retain the
checkpoint's quantization metadata and set `dequantize_base_checkpoint: true`.
Attention KV and index quantize/dequantize boundaries remain part of every
forward, with straight-through gradients. Trained checkpoints preserve released
parameter names and logical Engram rows with floating-point weights.

Both text recipes disable the vision tower. The model also provides the
released image encoder, projector, image delimiters, and visual router bias,
using the existing DeepSeek V4 vision modules.

See the [Slurm launcher guide](/job-launchers/slurm-cluster),
[installation guide](/get-started/installation), and
[model README](https://github.com/NVIDIA-NeMo/Automodel/blob/main/nemo_automodel/components/models/deepseek_v41/README.md)
for the surrounding workflow. Compilation caches and communication prewarming
must match the chosen backend, topology, and local input shapes.

## Historical validation and current scope

The original `torch_mm` comparison at commit
`0d5919a5a506dd35dc4f55769410feb98ae854b8` covers all 40 layers, 4,096 positions,
and all 129,280 vocabulary entries against the pinned checkpoint's unchanged
official `inference/` code. Official TP1 is compared with native EP4 and four
Engram row owners using HybridEP and TileLang. Rank 0 supplies one valid global
sample; the other ranks use masked inputs and participate in communication.

The native run streams one production block at a time while carrying its own
residual, mHC, and CSA2 state. Embedding, final norm, and output head weights are
replicated. This is complete-backbone streamed-forward evidence; it does not
establish resident multi-node training or a new parity result for this PR.

| Metric | Original streamed-40 `torch_mm` result |
|---|---:|
| Mean KL | 0.0017376351 |
| P95 KL | 0.0005163713 |
| Maximum KL | 0.8451328874 |
| Logit cosine | 0.9946222187 |
| Top-1 agreement | 99.58496094% |

The fixed mean-KL and cosine gates failed. These measurements remain the
recorded baseline for the selected backend; earlier zero-KL results used
`torch_linear`. Historical checkpoint-restoration and finite-gradient results
also have their own source and topology scope. TileLang continuation was not
bitwise reproducible, and no successful resident 100-update or convergence
result is claimed.

Training uses unpacked, right-padded, zero-based sequences. THD packing, TP,
PP, CP, incremental generation caches, and million-token training are outside
this implementation. Image inputs also require unpacked batches. Indexers
remain frozen because hard top-k selection has no language-model gradient.
Indexer distillation, DSpark draft training, and the report's Engram pretraining
optimizer are outside this fine-tuning implementation.
