[DeepSeek-V4 Pro](https://huggingface.co/deepseek-ai/DeepSeek-V4-Pro) is a fine-grained mixture-of-experts language model supported by NeMo AutoModel's native DeepSeek-V4 implementation.

## Fine-Tune DeepSeek-V4-Pro

This configuration uses PP8 and EP64 across 512 GPUs (64 nodes with 8 H100 GPUs
per node), so it is not a single-node example. Launch it through Slurm or an
external `torchrun` environment using the topology declared in the recipe. For
example, after setting the rendezvous host and port for your cluster:

```bash
torchrun --nproc-per-node=8 \
  --nnodes=64 \
  --rdzv-backend=c10d \
  --rdzv-endpoint="${MASTER_ADDR}:${MASTER_PORT}" \
  -m nemo_automodel.recipes.llm.train_ft \
  -c examples/llm_finetune/deepseek_v4/deepseek_v4_pro_hellaswag_all_tilelang_pp8_ep64_20steps.yaml
```

See the [Launcher Guide](/job-launchers/slurm-cluster) for cluster-specific
setup and the [Large MoE Fine-Tuning Guide](/recipes-e2e-examples/large-moe-fine-tuning)
for the full multi-node environment setup.

### Notes for Cold Starts and Large Rank Counts

- **First step is long.** On 64 H100 nodes a cold start spends 38-40 minutes before step 0:
  each rank JIT-compiles its HybridEP and TileLang kernels, and pipeline parallelism runs those
  compiles stage after stage. The recipes therefore set `dist_env.timeout_minutes: 120`.
  Point `NEMO_HYBRIDEP_JIT_CACHE` at a shared directory to reuse the HybridEP kernels
  across runs.
- **Resolve the Hub once, not 512 times.** With hundreds of ranks resolving
  `deepseek-ai/DeepSeek-V4-Pro` and the dataset online at start-up, the anonymous Hugging Face
  rate limit (HTTP 429) is hit and `huggingface_hub` retries with long back-offs. Pre-download the
  snapshot and the dataset once (`huggingface_hub.snapshot_download`, `datasets.load_dataset`)
  into a shared `HF_HOME` and run with `HF_HUB_OFFLINE=1`; the recipe then starts with zero Hub
  requests.
