[DeepSeek-V4.1 Flash](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash) combines a 40-layer causal encoder/decoder backbone, 384 routed experts and one shared expert per layer, top-6 routing, CSA2 cross-layer compression and index reuse, hierarchical candidate selection, single-pass mHC, and Engram conditional memory at layers 1 and 14. The approximately 552B backbone is accompanied by 196B Engram parameters.

The port includes optional image processing, the released vision encoder and aligner, image delimiters, and visual router bias. Its checkpoint/reference revision is [`df42c109f1defefcbfcedbe7d905718a12266e40`](https://huggingface.co/deepseek-ai/DeepSeek-V4.1-Flash/tree/df42c109f1defefcbfcedbe7d905718a12266e40). Numerical comparisons use the unchanged HF-hosted `inference/` code; the dump does not contain a Transformers modeling implementation.

<Note>
Validation of the migrated implementation is pending. Historical results below belong to the original implementation, and the full-resident 16-node training attempt failed with OOM after one optimizer update.
</Note>

## Training Recipes

| Recipe | Scope |
|---|---|
| [`deepseek_v41_flash_hellaswag_ep64_16nodes.yaml`](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_finetune/deepseek_v41/deepseek_v41_flash_hellaswag_ep64_16nodes.yaml) | Full text-backbone validation, both Engram tables trainable, 16 nodes × 4 GB200, 100 updates with validation/checkpoints every 50 |
| [`deepseek_v41_flash_hellaswag.yaml`](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_finetune/deepseek_v41/deepseek_v41_flash_hellaswag.yaml) | Existing generic text SFT configuration with frozen Engram tables; separate batch, optimizer and checkpoint settings |

CUDA model construction defaults to `torch_mm` experts, HybridEP dispatch and TileLang attention, with `torch` linears and `torch_fp32` normalization. The 16-node recipe selects these explicitly. Its 64 ranks must share one verified NVLink domain. EP64 and Engram's 64 row owners use distinct sharding mechanisms; dense weights use FSDP2, and experts have no additional FSDP shard axis. TP, PP and CP are all 1. Global batch 64 with local batch 1 gives no gradient accumulation.

Activation checkpointing and reshard-after-forward are enabled. BF16 training retains explicit FP32 parameters and mHC coefficients across FSDP boundaries; the language-model head returns FP32 logits. The default `gate_bias_update_factor: 0.0` preserves released router biases, while a positive MoE override enables updates. TE FusedAdam uses FP32 moments and int16 remainders for BF16 master weights. The target is fine-tuning rather than a reproduction of the report's Engram pretraining optimizer.

Follow the [Launcher Guide](/job-launchers/slurm-cluster) to supply the allocation, rank ordering and runtime environment. The recipe header describes shared snapshot and checkpoint-directory overrides. Use the pinned snapshot on every rank and keep output checkpoints outside the source checkout. The requested 100-update schedule does not establish that this topology fits in memory: the original run completed update 0 and OOMed during the next backward, even with AC and resharding.

## Implementation Scope

- Engram is enabled but frozen by default (`engram_trainable: false`). The 16-node recipe explicitly enables training of both tables. The owner-sharded DTensors are excluded from FSDP all-gathers; gradients return to their row owners and receive the owner divisor once before clipping. Hashing requires `input_ids` and a fast tokenizer resolved at the configuration's checkpoint commit, or an explicitly supplied tokenizer. Meta materialization restores the tokenizer-derived map and deterministic hash buffers.
- Released FP8 dense weights, packed FP4 experts and rowwise FP8 tables initialize floating-point parameters. With `kv_cache_fake_quant: true`, FP8/NVFP4/MXFP4 KV and index quantize/dequantize boundaries remain in the forward, with straight-through training gradients.
- Shared MoE uses FP32 accumulation of routed contributions and the shared expert before the final BF16 cast. `torch_linear` is an optional explicit reference-oriented backend; it is not the selected `torch_mm` recipe backend.
- Indexer parameters are frozen because hard top-k supplies no language-model gradient. DSpark drafts under `mtp.*`, incremental KV caching, bounded decoder replay, TP, PP and CP are outside the port.
- Packed text uses the PR's THD path with document metadata and an external recipe loss. The standalone `labels` API supports unpacked batches only. Images also require unpacked token batches. `DeepseekV41Processor` handles ordinary text/image conversations; the model accepts patch tensors, image grids and per-token image-type markers. Packed images are rejected.
- Omitting vision metadata creates a disabled tower; loading the released vision configuration enables its layers. Both HellaSwag recipes explicitly disable the tower. Text-only gates still retain `bias_vl`.
- `checkpoint.dequantize_base_checkpoint: true` enables normal released-weight initialization. The adapter also exposes bounded `load_from_checkpoint` for already materialized, distributed models, with key/shape, local FP32 storage and expert-alias checks. Trained floating-point exports preserve released names and logical Engram rows. Quantized re-export is not established.

See the [model README](https://github.com/NVIDIA-NeMo/Automodel/blob/main/nemo_automodel/components/models/deepseek_v41/README.md) for loader APIs, precision details and input layouts. Million-token training and full-model convergence have not been validated.

## Historical Validation and Migration Status

The original `torch_mm` result at commit `0d5919a5a506dd35dc4f55769410feb98ae854b8` compared all 40 layers, 4,096 positions and all 129,280 vocabulary entries against the unchanged official TP1 reference. Native EP4/Engram-owner4 used HybridEP and TileLang, with one valid global sample on rank 0 and masked participation on the other ranks. It streamed one production block at a time while carrying native residual, mHC and CSA2 state; shared embedding, norm and head weights were replicated.

| Metric | Original streamed-40 result |
|---|---:|
| Mean KL | 0.0017376351 |
| P95 KL | 0.0005163713 |
| Maximum KL | 0.8451328874 |
| Logit cosine | 0.9946222187 |
| Top-1 agreement | 99.58496094% |

The fixed mean-KL and cosine gates failed. These are original streamed-forward measurements, not a numerical pass for the migration or evidence of full-resident training. Earlier exact `torch_linear` results belong to that different backend.

Original reduced-width 40-layer EP2/expert-FSDP2 validation at commit `69a192aaa183efc6aae317255f6d8f0a3a906499` used workspace-only wrappers for real interruption and fresh-process checkpoint restoration, including TE optimizer/int16 masters, RNG, loader and progress. Earlier trajectory probes were debugging evidence rather than final proof of Engram scaling, and TileLang continuation was not bitwise reproducible. Migration tests remain pending; no successful full-resident 100-update or convergence result is claimed.
