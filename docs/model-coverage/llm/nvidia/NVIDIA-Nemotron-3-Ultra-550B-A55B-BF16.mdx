[NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16) has a checked-in NeMo AutoModel recipe for text generation.
The Hugging Face configuration declares the `NemotronHForCausalLM` architecture.

## Quick Start

Follow the [installation instructions](/get-started/installation). This example fine-tunes all parameters on SQuAD using 32 nodes with 8 GPUs each. Complete [Recipe Setup](#recipe-setup), then run the command from the repository root on every node.

```bash
uv run torchrun --nnodes 32 --nproc-per-node 8 \
  --node-rank "$NODE_RANK" --master-addr "$MASTER_ADDR" --master-port 29500 \
  -m nemo_automodel.cli.app examples/llm_finetune/nemotron/nemotron_ultra_v3_squad.yaml
```

## Model Context

NVIDIA-Nemotron-3-Ultra-550B-A55B-BF16 is used for text generation. Its model size is 560.52B checkpoint parameters.

| Property | Value |
| --- | --- |
| Task | Text generation |
| **Architecture** | `NemotronHForCausalLM` |
| Parameters | 560.52B checkpoint parameters |
| Hidden Size | 8,192 |
| Attention | 64 attention heads / 2 key-value heads |
| Context Length | 262,144 tokens (checkpoint configuration) |
| Vocabulary Size | 131,072 |
| Experts | 512 routed / 1 shared / 22 selected per token |

### Recipe Setup

The [SQuAD recipe](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/llm_finetune/nemotron/nemotron_ultra_v3_squad.yaml) loads pretrained weights and trains on `rajpurkar/squad` with 4,096-token packs. It runs for up to 17 steps and enables checkpoint saving to `checkpoints/ultra_full_sft/`.

The recipe's `FusedLinearCrossEntropy` loss requires `cut-cross-entropy`, which is supplied by the `dev` dependency group. For a source installation, run `uv sync --locked --all-groups --extra all` from the repository root as shown in the [installation guide](/get-started/installation); `--all-groups` includes `dev`. Complete the Transformer Engine and HybridEP setup as well.

Use the [Slurm launcher guide](/job-launchers/slurm-cluster) to prepare the 32-node allocation. This example uses pipeline parallelism across four ranks (PP4) and expert parallelism across 64 ranks (EP64). Configure the same environment on every node with the selected Transformer Engine and HybridEP backends available. Set `NODE_RANK` to each node's unique rank from `0` to `31`, and set `MASTER_ADDR` to the reachable hostname or IP address of rank `0` on every node.

### Workflow Notes

The training benchmark initializes the model from configuration rather than loading pretrained weights. It uses synthetic data and a fake balanced gate for expert routing, and it disables checkpoint saving. Use it to measure training throughput; use the SQuAD recipe to fine-tune the checkpoint on real data.
