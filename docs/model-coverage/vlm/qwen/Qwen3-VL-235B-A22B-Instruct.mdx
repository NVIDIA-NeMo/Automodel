[Qwen3-VL-235B-A22B-Instruct](https://huggingface.co/Qwen/Qwen3-VL-235B-A22B-Instruct) has a checked-in NeMo AutoModel recipe for image-text-to-text.
The Hugging Face configuration declares the `Qwen3VLMoeForConditionalGeneration` architecture.

## Quick Start

Complete the [recipe prerequisites](#prepare-the-environment), then run from the repository root on each of 32 nodes with 8 GPUs. Set `NODE_RANK` to a unique value from 0 to 31 and `MASTER_ADDR` to the rank-0 node's address, reachable from every node.

```bash
uv run --no-sync torchrun --nnodes 32 --nproc-per-node 8 \
  --node-rank "$NODE_RANK" --master-addr "$MASTER_ADDR" --master-port 29500 \
  -m nemo_automodel.cli.app examples/vlm_finetune/qwen3/qwen3_vl_moe_235b.yaml \
  --step_scheduler.local_batch_size=4
```

### Prepare the Environment

Follow the [installation guide](/get-started/installation) and prepare the checkout's environment on every node. For a source installation, select the `vlm` and `moe` extras. The `moe` extra includes Transformer Engine through `cuda` and the pinned `deep_ep` package, which builds HybridEP; the standard `all` extra omits `moe`.

This multi-node recipe needs a HybridEP build with multi-node support. When building from source, set `HYBRID_EP_MULTINODE=1` and configure the CUDA and RDMA build dependencies as shown in the repository's [HybridEP container setup](https://github.com/NVIDIA-NeMo/Automodel/blob/main/docker/Dockerfile). Use the same prepared environment on all nodes; `--no-sync` keeps the launch from changing it.

The 32-node, 8-GPU launch is an example topology, not a hardware minimum. Changes to GPU counts also require compatible batch sizes and parallelism settings. PP and EP denote pipeline parallelism and expert parallelism. Every node needs access to the checkpoint and `mmoukouba/MedPix-VQA` dataset.

### Fine-Tuning Configuration

The Quick Start loads pretrained weights and trains on MedPix-VQA with the vision tower frozen and a collator limit of 2,048 tokens. The recipe sets `checkpoint.enabled: false`, so it does not save trained weights. Enable checkpoint saving and configure a persistent `checkpoint.checkpoint_dir` to retain the result.

The launch uses the recipe's CI local batch size of 4. With 256 GPUs and `pp_size=4`, there are 64 data-parallel ranks: a local batch of 4 gives the configured global batch of 256. The YAML's default local batch of 8 is incompatible with that global batch on this topology.

| Setting | Configuration |
| --- | --- |
| Hardware | GPU model not specified by the recipe |
| Strategy | Fully Sharded Data Parallelism (FSDP2); `tp_size=1`, `pp_size=4`, `cp_size=1`, `ep_size=32` |
| Nodes | 32 |
| Features | Transformer Engine, HybridEP (`dispatcher=hybridep`) |
| Advanced | `attn=sdpa`, `linear=te`, `experts=torch_mm`, `dispatcher=hybridep` |
