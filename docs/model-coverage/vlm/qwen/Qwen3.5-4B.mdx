Qwen3.5-4B is a dense vision-language model in Alibaba Cloud's Qwen3.5 series for image and multimodal understanding tasks.

Set up NeMo AutoModel with the [latest container](https://catalog.ngc.nvidia.com/orgs/nvidia/containers/nemo-automodel) or follow the [installation instructions](/get-started/installation).

## Quick Start

The example launches eight GPU workers. From the repository root, run:

```bash
uv run automodel --nproc-per-node=8 examples/vlm_finetune/qwen3_5/qwen3_5_4b.yaml
```

## Model Context

Qwen3.5-4B pairs a 4B-class language model with a vision encoder. The recipe loads pretrained weights for full fine-tuning on MedPix-VQA, trains both the vision tower and language model with fully sharded data parallelism (FSDP2), and saves checkpoints to `/tmp/checkpoints/qwen3_5_4b/`.

| Property | Value |
| --- | --- |
| Task | Image-Text-to-Text |
| Architecture | `Qwen3_5ForConditionalGeneration` |
| Language Model Size | 4B (upstream designation) |
| Parameters | Approximately 4.66B stored checkpoint parameters (Hugging Face metadata) |
| Hugging Face Organization | [Qwen](https://huggingface.co/Qwen) |
| Decoder Layers | 32 |
| Hidden Size | 2,560 |
| Attention | 24 Gated DeltaNet layers and 8 gated-attention layers |
| Gated Attention Heads | 16 query heads and 4 key-value heads |
| Context Length | 262,144 tokens (checkpoint configuration) |
| Vocabulary Size | 248,320 |

#### Validated Large-Model, Long-Context Scale

The Qwen3.5-MoE VLM training path has been validated at both
**397-billion-parameter model scale** and **128K context length**.
Qwen3.5-397B-A17B completed a 10-step end-to-end training run on 256 H100 GPUs
with FSDP2, context parallelism (CP64), expert parallelism (EP64), packed sequences, full activation checkpointing, and a
trainable vision tower. The workload mixed text, image, and video data and
included genuine examples of approximately 120K tokens.

The run maintained finite, decreasing loss, validating the training mechanics
for this combined large-model and long-context regime. It is not a model
convergence result. The public
[397B recipe](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/vlm_finetune/qwen3_5_moe/qwen3_5_moe_medpix.yaml)
provides a starting configuration for that checkpoint; use the
[122B EP8/CP32 recipe](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/vlm_finetune/qwen3_5_moe/qwen3_5_122b_128k_ep8cp32.yaml)
as the published 128K long-context reference.

Both published MoE recipes use MedPix-VQA and disable checkpoint saving. For source installations, add `--extra moe` to the [installation guide's](/get-started/installation) `uv sync --locked --all-groups --extra all` command to install HybridEP. Build HybridEP with `HYBRID_EP_MULTINODE=1` for these multi-node recipes and set `TORCH_CUDA_ARCH_LIST` for the target GPUs. Follow the [Dockerfile's HybridEP build setup](https://github.com/NVIDIA-NeMo/Automodel/blob/c79ba55eb77527138337288220df04bc5939483c/docker/Dockerfile#L150-L180) for communication dependencies (RDMA core, NCCL/DOCA, and NVSHMEM), `RDMA_CORE_HOME`, and CUDA include paths. The 122B recipe also uses Transformer Engine's `FusedAdam` from the `cuda` extra and `FusedLinearCrossEntropy`, which requires `cut-cross-entropy` from the `dev` dependency group. The `all` extra includes `cuda`, and `--all-groups` includes `dev`.

Dense Qwen3.5 and Qwen3.5-MoE support context-parallel vision frame sharding. The
Qwen3.5-MoE path composes expert and context parallelism with packed sequences; see the
[Context-Parallel Vision Frame Sharding guide](/development/cp-vision-frame-sharding).
