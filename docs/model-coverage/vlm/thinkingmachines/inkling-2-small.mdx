[Inkling-2-Small](https://huggingface.co/thinkingmachines/Inkling-2-Small) is a multimodal Mixture-of-Experts model from Thinking Machines Lab with 594B total and 17B active parameters. It accepts text and image inputs and generates text. NeMo AutoModel provides a native model implementation, image processor, and checkpoint adapter for it, separate from the [Inkling](/model-coverage/vision-language-models/thinkingmachines/Inkling) implementation.

## Model Reference

### Model Architecture

| Property | Value |
|---|---|
| **Task** | Image-Text-to-Text |
| **Architecture** | `Inkling2ForConditionalGeneration` |
| **Model type** | `inkling2` |
| **Parameters** | 594B total / 17B active |
| **Language model** | 48 layers, hidden size 4608, 48 query heads and 8 key-value heads, 1M-token context |
| **Experts** | 384 routed experts per layer, top-8 routing, expert width 2304, no shared experts |
| **Vision encoder** | 23-layer ViT, hidden size 1024 |
| **Checkpoint precision** | NVFP4 experts in layers 0-39, MXFP8 experts in layers 40-47, BF16 elsewhere |
| **HF Org** | [thinkingmachines](https://huggingface.co/thinkingmachines) |

## Architecture

The decoder has 40 sliding-window layers with a 1024-token window and 8 global layers (every sixth layer). Attention uses a learned relative-position bias instead of RoPE, L2-clipped queries and keys, short convolutions on keys and values, an output gate, and attention sinks. Attention residuals mix layer outputs within blocks of six layers.

Each MoE layer routes a token to 8 of 384 experts with a biased sigmoid router. The experts use a softcapped SwiGLU activation, and the final logits are softcapped at 30. Images use one token per 40x40 pixel patch. Inkling-2-Small has no audio input.

The release also ships a speculative-decoding drafter in `mtp.safetensors`. The recipes on this page train the base model and do not load the drafter.

## Checkpoint Loading

The released checkpoint stores routed-expert weights in NVFP4 for layers 0-39 and in MXFP8 for layers 40-47; all other weights are BF16. With `checkpoint.dequantize_base_checkpoint: true`, AutoModel decodes the experts into BF16 while loading, so you do not need to convert the checkpoint first. Training runs on the dequantized BF16 weights; it is not NVFP4 training.

Thinking Machines also publishes [Inkling-2-Small-MXFP8](https://huggingface.co/thinkingmachines/Inkling-2-Small-MXFP8), which stores every expert in MXFP8. The recipes below use the mixed NVFP4 and MXFP8 checkpoint.

## Example Recipes

| Recipe | Dataset | Trained Parameters | Hardware |
|---|---|---|---|
| [Full SFT, EP128](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/vlm_finetune/inkling2/inkling2_small_medpix_sft_ep128.yaml) | MedPix-VQA | Language model; vision encoder frozen | 16 nodes, 128 H100 GPUs |
| [LoRA, EP32](https://github.com/NVIDIA-NeMo/Automodel/blob/main/examples/vlm_finetune/inkling2/inkling2_small_medpix_lora_ep32.yaml) | MedPix-VQA | Rank-8 adapters on attention projections and routed experts | 4 nodes, 32 H100 GPUs |

Both recipes use FSDP2 with HybridEP expert dispatch, grouped `torch_mm` experts, and activation checkpointing, with no tensor, context, or pipeline parallelism. They pad or truncate each sample to 1024 tokens and disable checkpoint saving.

The full SFT recipe holds about 4.6B parameters per GPU (3 experts per layer) and uses Transformer Engine FusedAdam with FP32 master weights and BF16 Adam moments; see [Mixed-Precision Training](/development/mixed-precision-training). The LoRA recipe keeps the frozen BF16 base at about 37 GB per GPU.

<Note>
These layouts are sized from parameter and optimizer-state arithmetic. Full-model runs at this scale have not been validated yet.
</Note>

## Run the Recipes

Follow the [installation instructions](/get-started/installation) and the [SLURM cluster guide](/job-launchers/slurm-cluster). The environment needs Transformer Engine and HybridEP. Run one `torchrun` launcher per node, with `NODE_RANK` set to the node index and `MASTER_ADDR` set to the first node's hostname.

Full SFT on 16 nodes:

```bash
torchrun --nnodes=16 --nproc-per-node=8 \
  --node-rank="${NODE_RANK}" \
  --rdzv-backend=c10d --rdzv-endpoint="${MASTER_ADDR}:29500" \
  -m nemo_automodel.cli.app \
  examples/vlm_finetune/inkling2/inkling2_small_medpix_sft_ep128.yaml
```

LoRA on 4 nodes:

```bash
torchrun --nnodes=4 --nproc-per-node=8 \
  --node-rank="${NODE_RANK}" \
  --rdzv-backend=c10d --rdzv-endpoint="${MASTER_ADDR}:29500" \
  -m nemo_automodel.cli.app \
  examples/vlm_finetune/inkling2/inkling2_small_medpix_lora_ep32.yaml
```

To log to Weights & Biases, set `wandb.enable: true` and fill in `wandb.project` and `wandb.entity`.
