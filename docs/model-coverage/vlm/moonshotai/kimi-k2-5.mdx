[Kimi-K2.5](https://huggingface.co/moonshotai/Kimi-K2.5) has a checked-in NeMo AutoModel recipe for image-text-to-text.
The Hugging Face configuration declares the `KimiK25ForConditionalGeneration` architecture.

## Fine-Tune Kimi-K2.5

Follow the [installation instructions](/get-started/installation), then run the recipe from the repository root:

```bash
automodel examples/vlm_finetune/kimi/kimi25vl_medpix.yaml --nproc-per-node 8
```

Use the [Slurm launcher guide](/job-launchers/slurm-cluster) for the multi-node run.

## Save Trained Experts as INT4

Pass `quantization=True` when saving the in-memory trained model. Kimi K2.5
reuses its group-32 INT4 encoder for routed experts; shared experts, attention,
vision, and other weights retain their existing precision. Use a checkpointer
configured with `model_save_format="safetensors"` and `save_consolidated=True`:

```python
model.save_pretrained(
    "/exports/kimi-k25-int4",
    checkpointer=checkpointer,
    tokenizer=tokenizer,
    quantization=True,
    is_final_checkpoint=True,
)
```

Call this on every distributed rank. The consolidated checkpoint is written to
`/exports/kimi-k25-int4/model/consolidated`, with matching compressed-tensors
metadata. `Checkpointer.save_model(..., quantization=True)` provides the same
option. No old checkpoint or separate conversion script is needed.

<Note>
The default remains `quantization=False` for ordinary training saves. This is
post-training weight quantization, not QAT; evaluate quality before deployment
and keep an unquantized checkpoint for training resume. Merge PEFT adapters into
full weights before requesting quantized export. Kimi K3 uses the same save
flag for MXFP4 rather than INT4.
</Note>
