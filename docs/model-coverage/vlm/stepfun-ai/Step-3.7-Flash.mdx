[Step-3.7-Flash](https://huggingface.co/stepfun-ai/Step-3.7-Flash) is Stepfun AI's 198B-parameter mixture-of-experts (MoE) vision-language model, with approximately 11B parameters active per token according to its upstream model card. Upstream describes native image understanding. NeMo AutoModel provides full and LoRA recipes for supervised image-text fine-tuning on MedPix-VQA.

## Quick Start

Follow the [installation instructions](/get-started/installation) and complete the [recipe setup](#recipe-setup). This example uses 16 nodes with 8 GPUs each. Run from the repository root on every node, setting `NODE_RANK` to a unique value from 0 to 15 and `MASTER_ADDR` to the rank-0 node's reachable address.

```bash
uv run torchrun --nnodes 16 --nproc-per-node 8 \
  --node-rank "$NODE_RANK" --master-addr "$MASTER_ADDR" --master-port 29500 \
  -m nemo_automodel.cli.app examples/vlm_finetune/stepfun/step3p7_medpix_200b_ep32pp4.yaml
```

## Model Context

The upstream model card declares the image-text-to-text task. Both AutoModel recipes use MedPix-VQA images, questions, and text answers. The checkpoint contains 201.37B parameters.

| Property | Value |
|---|---|
| **Task** | Image-Text-to-Text; MedPix-VQA fine-tuning in both recipes |
| **Architecture** | `Step3p7ForConditionalGeneration` - upstream describes 198B total and approximately 11B active parameters |
| **Language Module** | Step-3.5-Flash-derived backbone, 45 layers, 288 experts, top-8 routing |
| **Vision Module** | 1.8B ViT, 47 layers, 728x728 image size |
| **Context Window** | 256K tokens (upstream checkpoint) |
| **Recipe Precision** | BF16 in both linked fine-tuning recipes |
| **HF Org** | [stepfun-ai](https://huggingface.co/stepfun-ai) |
| Parameters | 201.37B checkpoint parameters |
| Decoder Layers | 45 |
| Hidden Size | 4,096 |
| Attention | 64 heads for full attention; 96 heads for sliding-window attention |
| Context Length | 262,144 tokens (checkpoint configuration) |
| Vocabulary Size | 128,896 |

Both recipes set `max_length: 2048` for training and validation inputs. This 2,048-token recipe input limit is separate from the checkpoint's 256K (262,144-token) context configuration.

### Positioning

The upstream model card describes native image understanding from a sparse language backbone and a vision encoder. The workflows on this page cover supervised image-text fine-tuning on MedPix-VQA with full fine-tuning or LoRA.

### Architecture

- **Language backbone:** derived from Step-3.5-Flash with 45 layers, 288 experts, 8 activated experts per token, and a 256K checkpoint context length.
- **Vision backbone:** 1.8B-parameter ViT with 47 layers and 728x728 image inputs.
- **Precision:** the linked AutoModel recipes use BF16. The upstream model card also documents serving with separate FP8 and NVFP4 variants.

### Key Strengths

- **Native image understanding.** The upstream model card describes a vision encoder paired with a sparse language backbone.
- **Image-text inputs.** Both recipes use `Step3VLProcessor`, whose `__call__` accepts images and text.
- **MedPix fine-tuning.** Full and LoRA recipes train on image-question-answer examples from MedPix-VQA.

### Recipe Setup

Both recipes load pretrained `stepfun-ai/Step-3.7-Flash` weights and the `mmoukouba/MedPix-VQA` dataset from Hugging Face. Make the checkpoint and dataset accessible on every node. The full recipe uses 128 GPUs with pipeline parallelism (PP) of 4 and expert parallelism (EP) of 32; LoRA uses 64 GPUs with PP8 and EP8. These are example topologies, not hardware minimums. Use the [Slurm launcher guide](/job-launchers/slurm-cluster) to prepare the allocation.

Install the `vlm` and `moe` extras when setting up from source. The `moe` extra includes Transformer Engine and the pinned `deep_ep` package, which builds both DeepEP and HybridEP. The standard `all` extra omits `deep_ep`. The full recipe selects HybridEP; LoRA selects DeepEP. For native backend setup, follow the RDMA and NVSHMEM build configuration in the [AutoModel Dockerfile](https://github.com/NVIDIA-NeMo/Automodel/blob/main/docker/Dockerfile), including `HYBRID_EP_MULTINODE=1` for the multi-node HybridEP build.

Both recipes freeze the vision tower. The full recipe saves checkpoints under `vlm_checkpoints/step3p7_medpix_ep32pp4/`. The LoRA recipe sets `checkpoint.enabled: false`, so it does not save trained adapters. Enable checkpoint saving and choose a checkpoint directory and save interval to retain your LoRA training output.
