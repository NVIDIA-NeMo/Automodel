xLAM function-calling data pairs user requests with tool specifications and expected calls. The source is hosted as [Salesforce/xlam-function-calling-60k](https://huggingface.co/datasets/Salesforce/xlam-function-calling-60k).

## Task

**Function calling.** The upstream format stores tool definitions and answers as serialized JSON; the example retains that storage shape.

| Property | Description |
| --- | --- |
| Input | A user query and a set of callable tools. |
| Target | One or more function names with their argument values. |
| Modality | Text |
| Language | English |
| License Metadata | cc-by-4.0 |

## Example Record

This **synthetic example** uses invented values in selected source fields; it is not a copied dataset row.

```json
{
  "query": "Add 4 and 5.",
  "tools": "[{\"name\":\"add\",\"description\":\"Add two integers.\",\"parameters\":{\"a\":{\"type\":\"int\",\"required\":true},\"b\":{\"type\":\"int\",\"required\":true}}}]",
  "answers": "[{\"name\":\"add\",\"arguments\":{\"a\":4,\"b\":5}}]"
}
```

## Schema and Splits

The table describes the task-bearing fields in the example. The source may also include identifiers and other metadata.

| Field | Type | Meaning |
| --- | --- | --- |
| `query` | string | User request. |
| `tools` | JSON string | Tool names, descriptions, and parameter schemas. |
| `answers` | JSON string | Expected function names and argument objects. |

These are upstream splits or source files, before any AutoModel sampling or preprocessing.

| Configuration | Split or Source | Rows |
| --- | --- | --- |
| `dataset` | `train` | 60,000 |

The row count comes from the [upstream card at the linked revision](https://huggingface.co/datasets/Salesforce/xlam-function-calling-60k/blob/26d14ebfe18b1f7b524bd39b404b50af5dc97866/README.md) before local filtering.
