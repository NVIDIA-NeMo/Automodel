Spider Schema supplies the database descriptions consumed alongside Spider questions and queries in. The source is hosted as [richardr1126/spider-schema](https://huggingface.co/datasets/richardr1126/spider-schema).

## Task

**Database-schema lookup for text-to-SQL.** This is a companion corpus of database descriptions. It provides context rather than question/answer supervision.

| Property | Description |
| --- | --- |
| Input | The database ID attached to a Spider question. |
| Target | The database schema used as context for SQL generation. |
| Modality | Text |
| Language | en |
| License Metadata | cc-by-4.0 |

The upstream metadata says CC-BY-4.0, while its prose cites CC-BY-SA-4.0 for Spider. Consult the upstream source for this discrepancy.

## Example Record

This **synthetic example** uses invented values in selected source fields; it is not a copied dataset row. Media paths, when shown, stand in for binary image or audio data and do not refer to downloadable files.

```json
{
  "db_id": "synthetic_library",
  "Schema (values (type))": "books : id (number) , title (text)",
  "Primary Keys": "books : id",
  "Foreign Keys": ""
}
```

## Schema and Splits

The table describes the task-bearing fields in the example. The source may also include identifiers and other metadata.

| Field | Type | Meaning |
| --- | --- | --- |
| `db_id` | string | Database identifier. |
| `Schema (values (type))` | string | Tables, columns, and column types. |
| `Primary Keys` | string | Table and primary-key column pairs. |
| `Foreign Keys` | string | Relations between tables. |

These are upstream splits or source files, before any AutoModel sampling or preprocessing.

| Configuration | Split or Source | Rows |
| --- | --- | --- |
| `default` | `train` | - |

Counts come from [upstream metadata at the linked revision](https://huggingface.co/datasets/richardr1126/spider-schema/blob/e383e6f78716d2e50db5e80f084ece642ecb150f/README.md) before local filtering. A dash means this page does not assert a count for that source.

## Use with NeMo AutoModel

| Workflow | Example Setup | Recipe |
| --- | --- | --- |
| Schema-Conditioned Fine-Tuning | Companion to xlangai/spider; EP8 | [View YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/03429168a27bfffd10d109d2adf436b49f1c82a7/examples/vlm_finetune/nemotron_3_5_super_vl/nemotron_3_5_super_vl_spider_peft.yaml) |

**Adapter:** [`make_spider_dataset`](https://github.com/NVIDIA-NeMo/Automodel/blob/03429168a27bfffd10d109d2adf436b49f1c82a7/nemo_automodel/components/datasets/vlm/datasets.py).

This is a companion corpus, not an independently supervised task. `make_spider_dataset` loads the schema table, indexes it by `db_id`, and supplies the corresponding DDL in each Spider prompt. The same launch trains on the question/SQL dataset with these schemas.

The schema loader reads `train`; training and validation membership comes from the Spider question dataset.
