MedPix-VQA pairs medical images with questions and answers. The source is hosted as [mmoukouba/MedPix-VQA](https://huggingface.co/datasets/mmoukouba/MedPix-VQA).

## Task

**Visual question answering.**

| Property | Description |
| --- | --- |
| Input | A medical image and a question about it. |
| Target | A text answer grounded in that image. |
| Modality | Image and text |
| Language | English (`en`) |
| License Metadata | `apache-2.0` |
| Access | Public and ungated in the pinned Hub metadata. |

## Example Record

This **synthetic example** uses invented values in the source fields; it is not a copied dataset row. The `image_id` object illustrates an undecoded image value. Its path is a placeholder, not a downloadable file.

```json
{
  "image_id": {
    "path": "synthetic-xray.png",
    "bytes": null
  },
  "mode": "radiograph",
  "case_id": "synthetic-case-001",
  "question": "Which body part is shown?",
  "answer": "The hand."
}
```

## Schema and Splits

The pinned source metadata declares the following fields. The AutoModel loader uses `image_id`, `question`, and `answer`.

| Field | Type | Meaning |
| --- | --- | --- |
| `image_id` | image | Image value, despite the column name ending in `_id`. |
| `mode` | string | Publisher-provided mode or context for the image. |
| `case_id` | string | Case identifier. |
| `question` | string | Question associated with the image. |
| `answer` | string | Reference answer. |

These are upstream splits, before any AutoModel sampling or preprocessing.

| Configuration | Split | Rows |
| --- | --- | --- |
| `default` | `train` | 17,420 |
| `default` | `validation` | 3,080 |

Counts come from [upstream metadata at the linked revision](https://huggingface.co/datasets/mmoukouba/MedPix-VQA/blob/69eb219d477ab8699296da1fd6b89beb768042d3/README.md) before local filtering.

## Use with NeMo AutoModel

| Workflow | Example Setup | Recipe |
| --- | --- | --- |
| Full Fine-Tuning | Gemma 3 4B; 1,000 training rows | [View YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/03429168a27bfffd10d109d2adf436b49f1c82a7/examples/vlm_finetune/gemma3/gemma3_vl_4b_medpix.yaml) |
| LoRA Fine-Tuning | Gemma 3 4B; 1,000 training rows | [View YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/03429168a27bfffd10d109d2adf436b49f1c82a7/examples/vlm_finetune/gemma3/gemma3_vl_4b_medpix_peft.yaml) |

**Adapter:** [`make_medpix_dataset`](https://github.com/NVIDIA-NeMo/Automodel/blob/03429168a27bfffd10d109d2adf436b49f1c82a7/nemo_automodel/components/datasets/vlm/datasets.py).

The loader creates a user turn containing the image and question, followed by an assistant turn containing the answer. It keeps rows Arrow-backed and defers image decoding to data access. Both examples explicitly select `mmoukouba/MedPix-VQA`, overriding the loader's different default dataset ID.

The full fine-tuning example uses `train[:1000]` and `validation[:500]`; the LoRA example uses `validation[:100]`. The publisher describes splitting by image to avoid overlap between training and validation.
