FineProofs-SFT pairs Olympiad-level mathematical problems with reasoning traces and proofs generated by DeepSeek-Math-V2, including a chat representation. The source is hosted as [lm-provers/FineProofs-SFT](https://huggingface.co/datasets/lm-provers/FineProofs-SFT).

## Task

**Mathematical reasoning and proof generation.**

| Property | Description |
| --- | --- |
| Input | A mathematical problem. |
| Target | A worked reasoning trace and proof, also represented as chat messages. |
| Modality | Text |
| Language | English |
| License Metadata | `apache-2.0` |

## Example Record

This **synthetic example** uses an elementary problem and invented values in selected source fields to illustrate the format; it is not a copied dataset row.

```json
{
  "problem": "Show that the sum of two even integers is even.",
  "reasoning_content": "Write the integers as 2a and 2b.",
  "proof": "Their sum is 2(a+b), which is even.",
  "messages": [
    {
      "role": "user",
      "content": "Show that the sum of two even integers is even."
    },
    {
      "role": "assistant",
      "content": "<think>Write the integers as 2a and 2b.</think>\n\nTheir sum is 2(a+b), which is even."
    }
  ]
}
```

## Schema and Splits

The table describes the task-bearing fields in the example. The source may also include identifiers and other metadata.

| Field | Type | Meaning |
| --- | --- | --- |
| `problem` | string | Mathematical problem statement. |
| `reasoning_content` | string | Reasoning trace extracted from the assistant's `<think>` block. |
| `proof` | string | Proof text. |
| `messages` | list of objects | Chat messages with string `role` and `content` fields; assistant content preserves the `<think>` block and proof. |

The table shows the `default` Hub configuration. Other configurations, when available, are listed on the [Hub dataset page](https://huggingface.co/datasets/lm-provers/FineProofs-SFT).

| Configuration | Split or Source | Rows |
| --- | --- | --- |
| `default` | `train` | 4,281 |

Counts come from [upstream metadata at the linked revision](https://huggingface.co/datasets/lm-provers/FineProofs-SFT/blob/73661e62811cf2940a0d3f82788a4f4332204c2f/README.md) before local filtering.

## Use with NeMo AutoModel

| Workflow | Example Setup | Recipe |
| --- | --- | --- |
| Chat Fine-Tuning | Qwen2.5 0.5B; 2,048-token limit | [View YAML](https://github.com/NVIDIA-NeMo/Automodel/blob/03429168a27bfffd10d109d2adf436b49f1c82a7/examples/llm_finetune/qwen/qwen2_5_0p5b_instruct_fineproofs_chat.yaml) |

**Adapter:** [`ChatDataset`](https://github.com/NVIDIA-NeMo/Automodel/blob/03429168a27bfffd10d109d2adf436b49f1c82a7/nemo_automodel/components/datasets/llm/chat_dataset.py).

The recipe reads the `messages` column, uses the tokenizer's chat template, and sets `mask_reasoning_content: false`. It truncates at 2,048 tokens. The recipe does not select the upstream `all` configuration; the default configuration has a different row count.

Training uses `train[:1024]`; validation uses the non-overlapping `train[1024:1152]` slice. The loader shuffles the upstream training split with seed `1111` before taking either slice. These are recipe holdouts from the upstream training split.
